## 二、怎么复现（这是"没有事后补造"的证据）

```bash
node scripts/export-learnbuddy-records.mjs --pdf
```

- **输入**：LearnBuddy 写在开发者本机的原始日志
  （`<家目录>/.learnbuddy/projects/<工作区目录名>/<会话 ID>.jsonl`）。
  本项目换过一次工作区目录，脚本**两个桶都收**，否则会漏掉 09-16 至 09-21 的前半程。
- **输出**：本目录下的 md 与 pdf。
- 脚本**不调模型、不做摘要**，是纯机械转换；除脱敏替换与排版转义外，文档里每个字都出自原始日志。
- ⚠️ **本文档是快照**：LearnBuddy 日志仍在写入（导出时有一条会话尚未结束），
  原始文件增长后再跑，结果会随之变化。
- 📌 脚本**刻意没有接进 `verify:*` 门禁链**：它不是回归测试，且会读家目录文件，
  不该在每次 `verify:predeploy` 时被触发。

## 六、维护约定

- **重新导出**：`node scripts/export-learnbuddy-records.mjs --pdf`
  （参数可用环境变量调：`LEARNBUDDY_REPLY_CAP` / `LEARNBUDDY_HEAD` / `LEARNBUDDY_TAIL`；
  换机器时用 `--projects-dir` 指定原始日志根目录；只统计不写盘用 `--dry-run`）。
- **单独跑敏感检查**：`npm run verify:sensitive` —— 本目录的三个文件都在其扫描范围内，
  当前结论 **17 项通过 / 0 失败**。
- **不要手工编辑**本目录的 md：它是脚本产物，手改会在下次导出时被覆盖，
  也会破坏"机械转换、可复现"这条证据链。要改口径就改脚本。
