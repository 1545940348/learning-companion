## 🔀 并行执行视图

> 目的：三个人（或三个 Agent 会话）能**同时开工而不互相等待、不互相覆盖**。
> 用法：先看下面的「文件所有权」确认自己要改的文件归属，再按「可立即开始」挑活。

### 并行原则

1. **依赖只看两件事**：要不要改 `packages/contracts`（契约）、要不要碰别人的目录。
2. **契约变更一律串行**：`packages/contracts` 同一时间只允许一个变更加在飞 ——
   它被 A/B/C 三方消费，两个契约变更并行必然产生"谁先谁后"的语义问题。
3. **文档不要并行写同一个文件**：`todo.md` / `知识库.md` 由 C 汇总落笔，
   其他人用 PR 评论或对话提出，避免并行编辑冲突。
4. **未实现的能力继续如实标注**：并行推进时最容易出现"为了演示好看先写上"，这是红线。

### 文件所有权（防冲突）

| 路径 | 唯一所有者 | 并行注意 |
|---|---|---|
| `packages/contracts/**` | **C** | **必须串行**。改完要 A、B 确认后同步 |
| `apps/server/**` | **C** | 含路由、store、构建配置、脚本 |
| `packages/teaching/**` | **B** | 提示词、图谱、校验、题目都在此 |
| `apps/web/**` | **A** | — |
| `docs/changelogs/**`、`docs/reviews/**` | 各人写各自文件 | 文件名带 `-A-`/`-B-`/`-C-` 前缀，不会撞 |
| `docs/todo.md`、`docs/知识库.md`、`docs/README.md` | **C 汇总改** | **多人同时改必然冲突** → 他人提，C 落笔 |
| `docs/specs/**` | 任何人 | **不改**：正本只追加新版本，不改写旧版本 |
| `.learnbuddy/**` | 各自 | 已被 git 忽略，可随意放临时产物 |

