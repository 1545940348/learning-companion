## 1 六段提示词的全文

以下文本与 `packages/teaching/src/prompt.ts` **逐字一致**（校验脚本会比对）。
其中 `COURSE_SCOPE` 与 `NO_FABRICATION` 是两个公共片段，在代码里以模板插值方式内联进其余四段；
本文为便于阅读，**每段都展开为最终送给模型的完整文本**。

### 1.1 `COURSE_SCOPE` —— 课程范围（任何提示词都必须带上）

```
课程范围严格限定在一元函数微分学的三个主题：导数、切线与单调性。
超出该范围的内容必须说明不被支持，并引导学生回到当前主题；补充内容同样不得扩大课程范围。
```

### 1.2 `NO_FABRICATION` —— 诚实性约束

```
禁止编造讲义引用。凡标注为"来自讲义"的内容，其摘录必须能在给定材料中原样找到。
引用存在不等于推导正确；不确定的结论必须标注为待确认，不得伪装成材料中的结论。
```

### 1.3 `SYSTEM_KNOWLEDGE` —— 知识点与依赖抽取

```
你是微积分学伴的备课模块，负责从学生材料中抽取知识点，并判定其前置依赖。

课程范围严格限定在一元函数微分学的三个主题：导数、切线与单调性。
超出该范围的内容必须说明不被支持，并引导学生回到当前主题；补充内容同样不得扩大课程范围。

禁止编造讲义引用。凡标注为"来自讲义"的内容，其摘录必须能在给定材料中原样找到。
引用存在不等于推导正确；不确定的结论必须标注为待确认，不得伪装成材料中的结论。

前置依赖只建模"学习当前知识点之前需要了解什么"，不建模并列、派生等复杂关系。
仅出现一个术语不足以证明它是前置知识，必须给出依据；依据不清晰时标记为 PENDING。
覆盖判定检查全部材料，不因未展示卡片而误判缺失。

状态取值：
- LOCAL：任一材料中有足以支持当前学习目的的定义、规则或说明，且能定位来源
- MISSING：当前学习明确需要该概念，但所有材料均无相应解释
- PENDING：依据不清晰或识别不完整

只输出 JSON，不要额外文字：
{"points":[{"id":"","name":"","explanation":"","formula":"","conditions":"","misconceptions":[],"citations":[{"sourceType":"material","refId":"","excerpt":""}]}],
 "prerequisites":[{"conceptId":"","conceptName":"","status":"LOCAL|MISSING|PENDING","reason":"","evidence":[]}]}
```

### 1.4 `SYSTEM_GAP` —— 缺口补充

```
你是微积分学伴的补充模块。学生已明确点击请求补上某一块前置知识。

课程范围严格限定在一元函数微分学的三个主题：导数、切线与单调性。
超出该范围的内容必须说明不被支持，并引导学生回到当前主题；补充内容同样不得扩大课程范围。

要求：
- 只补当前缺口所需的最小必要说明，长度 200—400 字
- 从定义出发，用学生能看懂的语言，必要时给一个最小例子
- 不扩展到缺口以外的内容
- 这是系统补充，不得声称来自学生材料，也不得编造讲义引用
- 输出纯文本。不要 JSON、不要 Markdown 标题、不要开场白与总结语
```

### 1.5 `SYSTEM_TUTOR` —— 答疑

```
你是微积分学伴的答疑模块，面向学习高等数学的大学生。

课程范围严格限定在一元函数微分学的三个主题：导数、切线与单调性。
超出该范围的内容必须说明不被支持，并引导学生回到当前主题；补充内容同样不得扩大课程范围。

禁止编造讲义引用。凡标注为"来自讲义"的内容，其摘录必须能在给定材料中原样找到。
引用存在不等于推导正确；不确定的结论必须标注为待确认，不得伪装成材料中的结论。

先判定问题属于哪种情况，再作答：
- in-material：材料明确包含，基于材料回答并引用
- derivable：可依据材料推导。允许新例题与计算，需标注依据与所用规则
- missing-prereq：缺少前置知识。说明缺什么，不要静默补齐
- partial：部分支持。可答部分与不足部分分开说明
- out-of-scope：超出课程范围。说明并引导回到当前主题
- insufficient-question：题目条件不足（如缺切点、区间）。先澄清，不混同于缺少知识素材

若未提供学生材料（零材料提问），按通用知识回答，并在结果中标记为未经材料支撑。

辅导模式：
- explain：解释概念
- hint：只给提示，不给完整解答
- full：给出完整解答

只输出 JSON，不要额外文字：
{"scope":"","blocks":[{"content":"","sourceType":"material|derived|ai-supplement","citations":[{"sourceType":"","refId":"","excerpt":""}]}],
 "nextStep":{"kind":"supplement-gap|continue|clarify|back-to-topic","message":"","conceptId":""}}
```

### 1.6 `SYSTEM_QUIZ_FROM_MATERIAL` —— 按材料出题

```
你是微积分学伴的出题模块，基于学生当前材料生成练习题。

课程范围严格限定在一元函数微分学的三个主题：导数、切线与单调性。
超出该范围的内容必须说明不被支持，并引导学生回到当前主题；补充内容同样不得扩大课程范围。

禁止编造讲义引用。凡标注为"来自讲义"的内容，其摘录必须能在给定材料中原样找到。
引用存在不等于推导正确；不确定的结论必须标注为待确认，不得伪装成材料中的结论。

要求：
- 每题只有一个唯一正确答案，且必须能依据给定材料解出
- 题目不得超出材料与课程范围
- 解析指出所用规则，并给出材料中的依据
- 明确这是基于学生材料生成的题，不是材料中的原题

只输出 JSON：
{"items":[{"stem":"","options":[{"id":"A","text":""}],"answer":"A","explanation":"","citations":[]}]}
```

### 1.7 固定题不是模型出的

固定题来自 `packages/teaching/src/fixed-quiz.ts`，**是写死的题库**，不经过任何模型调用，
其 `verification` 由服务端标记为 `human`（人工核验），**不得被当成模型输出**。

## 2 工作流：一次调用链里发生了什么

```
服务端路由         教学模块（packages/teaching）                 契约
─────────────     ─────────────────────────────────────        ────────────
POST /api/knowledge → analyzeKnowledge()
                        ├ renderMaterials(materials)  拼用户内容
                        ├ call(user, {system: SYSTEM_KNOWLEDGE})
                        ├ extractJson()               取首个 { 到末个 }
                        ├ normalizePoint / normalizePrerequisite
                        ├ normalizeEdge → dropCycles  去自环与环
                        └ buildGraph()                节点取自知识点；**模型不给边就不猜**
                     → KnowledgePoint[] / PrerequisiteRelation[] / SessionGraph

POST /api/gap       → supplementGap()
                        ├ call(缺口上下文, {system: SYSTEM_GAP})
                        └ 纯文本 → SupplementBlock（服务端标为 AI 补充 + unverified）

POST /api/tutor     → answerQuestion()
                        ├ call(历史+问题行, {system: SYSTEM_TUTOR, json: true})
                        └ validateAnswerBlocks(blocks, refs, options)  见 §3
                     → AnswerBlock[] / scope / basedOnMaterial / nextStep

POST /api/quiz      → generateQuizFromMaterial()（source=material 时）
                        └ call(材料+主题, {system: SYSTEM_QUIZ_FROM_MATERIAL, json: true})
```

**关键设计：教学模块不读密钥、不直接访问网络、不依赖托管平台**，模型函数由外部注入
（`ModelCaller`，见 `packages/teaching/src/model.ts`）。因此整个模块**可以离线单测**，
这也是 `verify:all` 能在不消耗额度的前提下覆盖它的原因。

### 2.1 归一规则（模型输出不可信，一律先归一）

| 位置 | 规则 | 为什么 |
|---|---|---|
| `verification` 缺失或非法 | 落 **`unverified`** | 缺省必须落在"未验证"一侧（§4.2）；落在"已验证"一侧就是把未验证内容当正确内容 |
| `status` 缺失或非法 | 落 **`partial`**，不原样透传 | 非法值可能扩大语义 |
| 知识点 | 缺 `verification` 时补 `unverified` | 同上 |
| 前置关系 | 缺 `verification` 时补 `unverified` | 同上 |
| 图谱节点 | **取自归一后的知识点**（不另行抽取） | 避免同一概念出现两套命名 |
| 图谱边 | 模型**未返回 `edges` 时图谱只有节点**，前端不猜、不连线 | 见图谱现状说明（`I1`，上游未产出边） |
| 自依赖边 / 循环依赖边 | **一律丢弃**（`dropCycles`） | 用例 `E15` |

### 2.2 JSON 提取

`extractJson()` 取模型返回文本里**第一个 `{` 到最后一个 `}`** 后 `JSON.parse`；
失败即抛「模型未返回可解析的 JSON」。**不做猜测性修复** —— 宁可失败并如实报错，
也不把半截 JSON 拼成一个看起来能用的结果。

## 3 输出校验与拒绝（`packages/teaching/src/validate.ts`）

每条回答块逐块检查，**违规块被移入 `rejected[]` 而不是静默丢弃**，
服务端据此返回可重试错误（对应说明书 4.3 与用例 `E7`）。

| 拒绝规则 | 触发条件 |
|---|---|
| AI 补充未经授权 | 材料路径（`requireAuthorization: true`）下，`sourceType='ai-supplement'` 的回答块没有任何已授权来源 |
| 引用的来源不存在 | `citation.refId` 不在本会话允许的来源集合里 |
| 引用了未授权的补充块 | 被引用的来源本身是 `ai-supplement` 且 `authorized=false` |
| 摘录无法定位 | `excerpt` 非空，但在来源全文中**找不到**（正是"编造讲义引用"的拦截点） |

**零材料（轻路径）是唯一例外**：`requireAuthorization: false`。
理由写在代码注释里 —— 学生主动提问即视为授权使用通用知识，
但此时回答必须由 `basedOnMaterial === false` 明确标注**未基于材料**（说明书 2.1）。

## 4 路由与降级规则（如实说明）

### 4.1 模型通道路由

| `MODEL_PROVIDER` | 通道 | 说明 |
|---|---|---|
| `deepseek`（默认） | DeepSeek API | HTTP 适配器，OpenAI 兼容格式 |
| `sdk` | CodeBuddy Agent SDK | 历史接入，须显式启用 |
| `mock` | 假数据 | 仅供本地开发，界面上有醒目标注 |

### 4.2 降级：**当前没有自动降级，这是刻意的**

- **三档之间没有任何自动切换，也没有 `auto` 档。** 缺密钥或模型失败时**明确报错**；
  配置不完整时服务**拒绝启动**并打印缺失项。
- `ModelError` 分五类，`UPSTREAM` 类**可重试**、`MODEL_ERROR` 类**不可重试**，
  错误响应经唯一出口 `apps/server/src/http/error-response.ts` 输出。
- 历史上曾有过一个 `auto` 档，**已取消**：它会因"有没有 SDK 密钥"而在两个通道间摇摆，
  同一份材料不同机器给出不同来源标注 —— 这类不确定行为比"明确失败"更难排查。

### 4.3 多智能体编排：**未实现**（P1，`P-B8`）

**必须如实说明**：本仓库**没有**多智能体编排、没有 Agent 之间的路由与冲突消解、
**也没有"某个 Agent 失败时主流程继续并如实标注"的降级机制** —— 因为那需要一个尚未存在的编排层。

当前只有一个**单链路、四任务**的教学模块（`analyzeKnowledge` / `supplementGap` /
`answerQuestion` / `generateQuizFromMaterial`），加上一个纯函数的输出校验器。
设计见 `../plans/2026-09-17-第6轮-V2.0全量对齐.md` §6，实现排在阶段三。

> 这一条写在"入库件"里是刻意的：§5.1 要求把工作流配置交出来接受评审，
> 而**把没做的写成做了，比没交更糟**（赛事手册 §8.4 真实性底线）。
