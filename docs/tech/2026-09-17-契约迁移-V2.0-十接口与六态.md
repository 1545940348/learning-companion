### 1.1 实施期追加：`NOT_IMPLEMENTED` 的由来

`/api/teacher`（阶段三）需要一个"路径存在但功能未交付"的表达。初稿直接复用 `NOT_FOUND` 配 501，
但本项目 V1.4/V2.0 收口的核心约定是**同一个错误码在所有路径上给出完全相同的状态码与 `retryable`**
（`http/error-response.ts` 的唯一表，PR #2 专为此重写）—— 复用会让 `NOT_FOUND` 一处 501、一处 404，
正是被修掉的病。因此新增独立错误码，语义也更准：**资源不存在 ≠ 功能未交付**。

同时修正一处默认值漂移：`config/env.ts` 的请求预算原本自带 `60_000` 字面量，与契约常量各写一份。
现改为 `readNumber(process.env.MODEL_TIMEOUT_MS, MODEL_TIMEOUT_MS)` —— **从契约读默认值**。
两个地方各写一个数字，必然再次漂移。

## 3 目标类型定义

### 3.1 依赖六态与验证状态

```ts
export type PrerequisiteStatus =
  | 'LOCAL'         // 材料已覆盖
  | 'SUPPLEMENTED'  // 已由 AI 补充
  | 'MISSING'       // 材料未覆盖，尚未补充
  | 'PENDING'       // 待确认：依据不清晰或识别不完整
  | 'VERIFIED'      // 已验证：补充或推导通过符号验证 / 人工核验
  | 'DISPUTED';     // 有争议：验证失败或来源冲突，需人工介入

export type VerificationStatus =
  | 'symbolic'      // 已符号验证
  | 'human'         // 已人工核验
  | 'unverified'    // 未验证（含超时）
  | 'failed';       // 验证未通过
```

**不变式**（§3.4，须在代码与回归脚本中同时体现）：

- `SUPPLEMENTED → VERIFIED` 仅当 `VerificationStatus ∈ {symbolic, human}`；
- `failed` 时 `SUPPLEMENTED → DISPUTED`；
- **`SUPPLEMENTED` 不因学生表示「已会」转为 `LOCAL`**；
- `MISSING → LOCAL` 仅当新增材料**确实提供说明**（仅提及不算）；
- 补充内容不跨会话迁移；新会话中同一概念回到 `MISSING`。

## 4 迁移顺序（不可打乱）

1. **C：先落类型** —— 改 `packages/contracts`，六态与验证状态先行。
2. **C：改 `MATERIAL_LIMITS` / `MODEL_TIMEOUT_MS`** —— 同步更新超限提示文案与超时文案
   （`budgetSeconds()` 已按配置推导，改常量即可，不会再出现"文案说 60 秒"的漂移）。
3. **C：`GET /api/quiz` → `POST /api/quiz`** —— 与 A 的调用改造**同批**。
4. **A：改调用侧** —— `apps/web/src/api.ts` 的 `quiz()` 与所有消费六态的分支。
5. **B：改教学模块** —— 任务函数签名、验证状态透出。
6. **C：新增三接口与回归脚本**。

> ⚠️ 第 3、4 步必须同批上线。`GET /api/quiz` 直接删除会立刻打断前端练习功能。

## 6 已知限制

1. `/api/teacher` 为阶段三交付，类型先落地、路由可后置；**已按本要求实现为
   `501 NOT_IMPLEMENTED`**，不返回空对象冒充已实现。
2. 图谱持久化仍为内存实现（§3.6 明确初赛不引入 Neo4j）；进程重启即失效，
   与本项目现行会话存储的限制一致，非新增限制。
3. `MODEL_TIMEOUT_MS` 由 60 s 升至 90 s 会**放宽**超时，需同步检查前端等待体验
   （A8 的加载与失败重试）。
