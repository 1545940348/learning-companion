## 一、决策：接口由 4 个扩展为 5 个

V1.1 的 4 个接口为 `parse`／`knowledge`／`tutor`／`quiz`。V1.2 新增 `POST /api/gap`，并扩展 `tutor` 与 `quiz` 的语义。

| 接口 | 变化 | 说明 |
|---|---|---|
| `POST /api/parse` | 语义变更 | 输出识别文本**可直接使用**，不再有"确认草稿"概念；新增低置信度标记 |
| `POST /api/knowledge` | 参数扩展 | 入参增加可选的"补充块"，用于接收 AI 补齐的内容 |
| `POST /api/tutor` | 语义扩展 | `材料版本` 可为空，表示轻路径会话；`mode` 收敛为 `explain`／`hint`／`full` |
| `POST /api/gap` | **新增** | 输入缺口概念 ID 与依赖理由 → 输出最小必要补充内容、补充块 ID、更新后的依赖状态 |
| `GET /api/quiz` | 参数扩展 | 新增 `source=fixed\|material`，`material` 表示基于当前材料生成 2 道题 |

## 二、为什么新增接口而不是复用 tutor

**方案 A（复用 tutor 的 mode）**：在 `tutor` 上增加 `mode=fill-gap`。
**方案 B（新增 gap 接口）**：独立接口。

**选择 B，理由**：

1. `tutor` 的输入契约围绕"提问—回答"设计，而缺口补充的输入是"缺口概念 ID ＋ 依赖理由"、输出是"要写入材料的补充块"，属于不同语义；
2. 补充内容需要落库成为材料的一部分（触发材料版本递增），与 `tutor` 的只读语义冲突；
3. 独立接口便于 A 单独做"补上这一段"的交互，不必等待答疑链路完成，符合三人并行的开发方式。

**代价**：接口数量 +1，C 需多维护一组正常／失败样例。判断为可接受。

## 三、依赖状态由三态扩展为四态

| V1.1 | V1.2 |
|---|---|
| LOCAL / MISSING / 待确认 | LOCAL / **SUPPLEMENTED** / MISSING / 待确认 |

**决策理由**：若不新增状态，AI 补齐后该概念会落入 LOCAL，导致"讲义材料"与"AI 补充"在依赖层被合并——这会直接破坏项目的核心亮点（来源区分），也会让 E3 与 E6 无法分别验证。

**不选择的替代方案**：给概念加布尔字段 `supplemented: true` 而状态仍为 LOCAL。
**否决理由**：状态与来源混在两个字段里，前端判断分支变多，且容易漏判。直接作为状态值更清晰。

## 四、授权模型变更：全局开关 → 按动作授权

- **原模型**：一个全局 `externalReference: boolean`，默认 false，开关变化时丢弃旧授权响应。
- **新模型**：取消全局字段。授权发生在一次 `POST /api/gap` 调用上，返回的补充块带授权标记与所属会话 ID。

**简化收益**：删除"开关变更时丢弃未完成回答"这一整类状态失效规则，也删除 E10 原先对应的实现分支。

**新增约束**：补充块必须绑定会话 ID，跨会话不可引用（对应用例 E10）。这一条由服务端在 `knowledge` 与 `tutor` 中校验，不由前端保证。

## 五、已知限制

1. 轻路径会话没有材料版本，"旧响应失效"的判定只能依赖会话 ID，粒度较粗；可能出现短窗口内的过期响应。当前接受该限制。
2. 缺口判定仍由模型生成，尚未收敛为固定规则表，可复现性依赖后续补充。
3. 按材料生成的题目质量依赖材料完整度，材料过于简略时可能生成超出材料范围的题；由 B 的输出校验拦截。
