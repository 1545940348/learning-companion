## 一、决策

模型推理改为**通过 CodeBuddy Agent SDK（`@tencent-ai/agent-sdk` 0.3.259）调用**，不使用自建 HTTP 客户端，
不自行猜测原始接口地址，也不套用通用聊天补全接口。

**认证方式**：由 SDK 读取环境变量，而非配置端点与请求头。

| 变量 | 值 | 说明 |
|---|---|---|
| `CODEBUDDY_API_KEY` | 密钥 | 仅存服务端 `.env`，不进仓库、不进对话记录 |
| `CODEBUDDY_INTERNET_ENVIRONMENT` | `internal` | 官方中国区环境 |
| `MODEL_TIMEOUT_MS` | `60000` | 对应说明书 5.3 的 60 秒超时 |

**同时废止的旧假设**：`.env.example` 原先设有 `MODEL_PROVIDER`／`MODEL_API_KEY`／`MODEL_BASE_URL`／
`MODEL_NAME` 四项，其中"base URL"与"固定模型名"在本接入方式下**均不存在**，已删除。

---

## 二、决策理由

1. **赛事平台自身提供的能力，优于自建第三方接入。** 说明书 5.1 原有一项不确定事项
   ——"第三方推理接口是否允许由 C 向赛事方确认"——随本决策自动消除。
2. **凭证与端点不由我们猜测。** SDK 封装了认证、环境选择与传输细节；一旦平台调整，
   升级 SDK 即可，不必我们去追接口变化。
3. **能力已被实测覆盖。** 项目两条关键路径（图文解析、结构化输出）都已确认可用，见下节。

## 三、实测事实（均为实际执行结果，非文档推测）

实测环境：Windows，Node v22.22.2，SDK 0.3.259，`CODEBUDDY_INTERNET_ENVIRONMENT=internal`。

| 项 | 结论 | 证据 |
|---|---|---|
| 文字调用 | 通过 | 提问 `f(x)=x²` 在 `x=1` 处的导数，返回"导数是 2"，`result-type=success` |
| 图片调用 | 通过 | 输入含公式的 PNG，正确转写 `f(x)=x^3-3x`、`f′(x)=3x^2-3`、临界点 `x=±1` |
| 模型名 | **由上游动态分配，且会变** | 同一份代码三次实测得到三组不同结果，见 3.1 |
| 结构化输出 | **SDK 有能力类型，但上游不兑现** | 两次传入 `options.outputFormat = { type:'json_schema', schema }`，`ResultMessage.structured_output` **均未返回**，见第四章 |
| 图片输入形式 | 支持 base64 与 URL 两种 source | `ImageContentBlock` → `Base64ImageSource` / `UrlImageSource` |

### 3.1 模型名三次实测结果（同一份代码，同一天）

| 时刻 | 输入 | 实际模型 |
|---|---|---|
| 18:42 | 纯文字 | `hy3` |
| 18:42 | 含图片 | `hy4-preview-f` |
| 19:05 | 纯文字 | `glm-5.3` |
| 19:05 | 结构化 | `glm-5.3` |
| 19:05 | 含图片 | `glm-5.3-flash` |
| 19:14 | 纯文字 | `minimax-m3` |

**结论：模型由上游动态分配，并非"按输入类型固定换档"。** 影响有三条：

1. 代码**绝不能硬编码模型名**（本适配层已按此实现，只从响应回读）；
2. **演示当天的回答风格、速度、质量可能与开发时不同** —— PPT 与视频里不得写死型号；
3. 固定题的答案一致性、以及"同一问题两次回答是否稳定"需要额外核验。

### 3.2 由实测得出的两条实现约束

**约束一：模型名只能回读，不能预设。** 理由见 3.1。`ModelResult.model` 取自
`SystemMessage.model` 与 `AssistantMessage.message.model`。这也让说明书 11.2
"接口名称与模型型号在验证后补充"有了确切答案：**型号无法预先确定，只能在每次响应里记录实际值**。

**约束二：输入形态保留两条已验证路径。** 纯文字走字符串 `prompt`；含图片走 `UserMessage`
异步流。两条路径都实测通过，故未合并为一条未经实测的统一路径——减少回归面。

## 四、关于结构化输出：一次被实测推翻的判断（对 B 影响最大）

### 4.1 最初的判断（已被推翻）

SDK 导出了 `OutputFormat` / `JsonSchemaOutputFormat` 类型，且有 `Options.outputFormat` 字段，
因此最初判断"结构化输出支持"，并据此认为 B 可以用 schema 约束来源字段，
把校验从"解析自由文本"降级为"校验已结构化的字段"。

**这个判断是错的：SDK 有类型，不等于上游会兑现。**

### 4.2 实测过程

| 实验 | 做法 | 结果 |
|---|---|---|
| 实验一（19:05） | 传入严格 schema（`additionalProperties:false` ＋ 全字段 required ＋ enum），提示词未额外强调 JSON | `structured_output` **未返回**。模型输出 markdown 散文，且自填的来源类别为"基础数学常识"，**不在 enum 允许值内** |
| 实验二（19:14） | 同样传入 schema，**并在系统提示词与用户消息中明确要求"只输出 JSON"** | `structured_output` **仍未返回**。但模型输出的是**干净纯 JSON**：`{"answer": 2, "sourceKind": "derived"}`，无 markdown 包裹，且 **enum 取值被遵守** |

两次实验横跨两个不同模型（`glm-5.3` 与 `minimax-m3`），结论一致。

### 4.3 结论与对 B 的直接影响

1. **`options.outputFormat` 在本链路上无效。** 不要依赖 `ResultMessage.structured_output`。
2. **改走可用路径：提示词要求 JSON ＋ 本层自行解析 ＋ 结构校验 ＋ 失败重试。**
   实验二证明这条路径**可行**：模型能输出干净纯 JSON，且能守住 enum。
3. **B4 三类来源校验的校验器仍然必要**，而且必须自己写。回退到"解析 + 重试"意味着
   说明书 5.1 提到的"无效来源或未授权内容不展示为正常答案，返回可重试错误"要由 B 承担。
4. **风险等级**：可控但高于原预期。E7（假引用不得作为正常答案展示）仍然可做，
   但依赖解析器与重试逻辑的正确性，需要 B 单独做测试。

`packages/contracts` 的 `ModelRequest.jsonSchema` 字段**保留**：它现在的作用从"约束上游"
变为"把 schema 文本注入提示词"的载体。冒烟脚本的 `structured` 命令提供了可复用示例。

## 五、⚠️ 已知限制与部署风险

### 5.1 本地网关依赖（最高优先级）

实测中，一次**故意用无效密钥**的调用返回了上游错误详情，其中包含：

```
(proxy: http://127.0.0.1:6657 -> https://copilot.tencent.com)
```

进一步核查本机环境：

- `127.0.0.1:6657` 处于 `LISTENING`（由本机进程提供）
- `CODEBUDDY_HOST=workbuddy-desktop`
- `HTTP_PROXY` / `HTTPS_PROXY` / `WORKBUDDY_PROXY_SOURCE` 均已设置

**判断**：2026-09-16 的文字与图片验证之所以成功，是因为 **WorkBuddy 桌面端正在本机运行并提供网关**。

**风险**：线上部署环境（云主机 / CloudStudio 沙箱）不会有 `workbuddy-desktop` 本地网关。
**模型调用能否在部署环境成立，目前尚未验证。**

**处理**：
- 本记录**仅记录该观察结果**，`127.0.0.1:6657` 与 `copilot.tencent.com` **不作为任何配置项写入代码**。
  理由与决策一致：不猜测、不硬编码原始 HTTP 地址。
- 列为 C2 的下一项验证任务：**在真实部署环境验证模型调用**，若不通则需向赛事方确认
  服务端调用的合规接入方式（可能是 endpoint 参数或云环境专用凭证）。
- 在此之前，**不得对外宣传"线上已接入模型"**，对应说明书 1.3 与 9.2 的诚实性要求。

### 5.2 其余限制

1. **单次调用耗时实测 12.7s / 21.0s / 17.7s。** 60 秒上限内，但波动明显。
   另外需注意：说明书 11.1 的视频脚本要求"0:20—0:45 零材料提问，30 秒得到解释"——
   当前耗时已接近该口径，**演示前必须实测能否稳定落在 30 秒内**。
2. **token 已有实测值，但额度折算仍未知。** 纯文字 70 入 / 43 出；结构化那次 76 入 / 352 出；
   **含图片 699 入 / 174 出 —— 图片约为纯文字的 10 倍**。`total_cost_usd` 三次均报 0，
   说明本环境不报告成本，额度口径需另找途径确认。**额度规划必须把图片路径单列。**
3. **结构化输出不可用**（已实测，见第四章）。B 必须自建解析与校验。
   **图片路径下 JSON 输出是否同样稳定，尚未验证**，联调时需补测。
4. **超时判定为单一来源。** 当前 `TIMEOUT` 只由本层 `AbortController` 触发，无法区分
   "上游超时"与"上游未响应"。粒度较粗，可接受。

**两层模型接口的分工**（避免混淆）：

- `ModelClient`（`@lc/contracts`）—— **传输层**接口，C 实现，SDK 类型不外泄；
- `ModelCaller`（`@lc/teaching`）—— **教学模块面向的注入函数**，B 只依赖它；
- 二者由 `apps/server/src/model/index.ts` 的适配器桥接：`ModelCaller` → `ModelClient`。

**`MODEL_PROVIDER` 的 `sdk` 档位是本次新增**：无密钥时不静默降级。
原因是 `auto` 档位在无密钥时会降级为 mock，若在演示或截图时不慎，容易把 mock 当成真实能力
（违反说明书 9.2 的诚实性要求）。
