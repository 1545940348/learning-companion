## 一、为什么选它

| 我们的需求 | 官方文档原文 | 结论 |
|---|---|---|
| 跑 Node + Express | 「Node.js：Express、Nest.js、Next.js、Koa」 | ✅ |
| **长驻进程** | 运行模式「持续运行：保持固定数量的实例持续运行」 | ✅ |

| 端口 | 监听**自定义端口**；Express 示例即 `--port 3000` | ✅ |

**免备案这一条最关键** —— ICP 备案需 1–20 个工作日，我们剩余工期不足以承担。

### ⚠️ 但"免备案"不等于"点开即用"（2026-09-18 补，**交付前必须知道**）

免备案的代价写在官方另一份文档里（<https://docs.cloudbase.net/service/alias>，原文摘录）：

> 「当访客使用浏览器通过『默认域名』（如 `*.app.tcloudbase.com`）访问云开发资源
> （**包括云托管**、网站托管、HTTP 网关等）时，用户通过浏览器直接访问的请求
> （`Sec-Fetch-Mode` 的值为 `navigate`）将会展示**『访问提示中间页』**，告知访客
> 当前环境仅供开发测试使用，内容未经合规审核」
> 「默认域名**仅建议用于开发测试**，严禁用于正式生产环境或**分发给大规模用户**」
> 「在生产环境使用默认域名**可能因流量触发风控而被关停**」
> 「移除中间页的**唯一合规途径**是配置并使用自定义域名」（自定义域名须完成 ICP 备案）

对我们意味着什么：

| 影响 | 处置 |
|---|---|
| 评委点开链接**不是直接看到学生界面**，而是先看到一张风险提示页，需点「确定访问」 | 把它写进交付说明与验收口径（§三 第 5 条），**不写成"点开即用"** |
| "把链接发给评委"恰好落在官方点名的"分发给大规模用户"里 | 演示当天把**最小副本数设为 1**，避免同一时间集中访问触发风控 |
| 想彻底消除 → 绑定自定义域名 → 需 ICP 备案 | **工期不够，接受这个限制**；若后续有余量，这是第一优先的补救项 |

> 这一条是 2026-09-18 的独立审查发现的：原文档只引了"免备案"那一面，
> 而它推出的"评委点开一个链接就能用"是**撑不住的结论**。引文本身没错，缺的是另一半。

## 二、部署步骤（控制台，约 5 分钟）

### 0. 前置

- 已在腾讯云开发创建环境（地域**上海**，套餐免费体验版即可）
- 本地已确认代码可用（见第四节）

### 1. 打包

在**仓库根目录**执行：

```bash
npm run pack:deploy
```

产出 `deploy-dist/`，并在末尾打印一份**安全检查报告**。
**必须看到「✅ 未发现 node_modules / .git / .env」才能继续** —— 这个目录会被上传到云端。

### 2. 上传

云托管控制台 → **通过本地代码部署**：

| 填写项 | 值 |
|---|---|
| 服务名称 | `calculus-companion` |
| 部署方式 | **上传代码包** |
| 代码包类型 | **文件夹** |
| 选择目录 | 上一步产出的 `deploy-dist/` |
| **端口** | **3000** |

### 3. 环境变量（首次先跑 mock）

在服务的环境变量里加：

```
MODEL_PROVIDER=mock
```

**为什么先填 mock**：第一次部署的重点是验证"管道通不通"（Node 版本、构建、启动），而不是跑真模型。
管道通了再换成 `deepseek` 并补密钥。

验证通过后换成真实通道：

```
MODEL_PROVIDER=deepseek
DEEPSEEK_API_KEY=<你的密钥>
DEEPSEEK_MODEL=deepseek-flash
```

> **密钥填在平台的环境变量里，不是仓库里。** 所以仓库公开也不会泄露，评委也无需配置任何东西。

### 4. 运行模式（重要）

默认的「始终自动扩缩容」**空闲 30 分钟后会缩容到 0** —— 而我们的**会话存在内存里**，
缩容后会话会丢。两种用法：

| 场景 | 最小副本数 | 理由 |
|---|---|---|
| **平时** | **0** | 无流量不产生费用 |
| **演示 / 录屏当天** | **1** | 无冷启动、会话不丢 |

即使保持 0 也能用：评委点开等几秒冷启动，只要**一次性走完流程**（不中断 30 分钟）就不会丢会话。

## 四、本地验证（部署前必须先过）

```bash
npm run verify:predeploy                # 一条命令全包：build:clean → build → verify:dist
                                        #              → verify:serve-web → verify:repo
npm run verify:serve-web -w @lc/server  # 同源托管专项，不消耗额度
npm run verify:all -w @lc/server        # 服务端全量回归（store+errors+guards+graph+symbolic），不消耗额度
npm run build                           # 构建服务端 + 前端
MODEL_PROVIDER=mock npm run start       # 用构建产物起服务
```

> 📌 **2026-09-20 补注**：上面两行的**项数不再写死** —— 它们每轮都在变（09-17 当时是
> `serve-web` 18 项、`all` 190 项；09-20 现值 `serve-web` **43**、`all` **263**、合计 **506**）。
> **现值一律查 `docs/知识库.md` §9 与 `todo.md` 的 `P-C5`**，别照抄本文件的历史数字。

然后浏览器打开 `http://localhost:3000`，应看到学生界面；刷新任意前端路由（如 `/dashboard`）不应 404。

**为什么要有这一步**：本地先证通，云端一旦出问题就能立刻判断是**平台配置**问题而不是**代码**问题。

## 五、本次实现要点

| 文件 | 作用 |
|---|---|
| `apps/server/src/http/serve-web.ts` | **新增**：同源托管。挂静态目录 + SPA 回退（仅 GET/HEAD；`/api` 与**任何带扩展名的路径**都不回退） |
| `apps/server/src/index.ts` | `/api` 路由之后、错误处理之前挂载同源托管 |
| `apps/server/src/config/env.ts` | 新增可选 `WEB_DIST_DIR`。留空自动探测，用于平台目录结构不同的兜底 |
| `Dockerfile` | 构建镜像（`node:22-alpine` + 上海时区 + 国内 npm 源） |
| `.dockerignore` | 排除 `node_modules` / `dist` / `.env` / `docs` / **`.npm-cache`** |
| `scripts/pack-deploy.mjs` | 打出干净的上传目录并自检（**排除名单 + 禁止后缀 + 体积上限**三道判定） |
| `apps/server/scripts/verify-serve-web.mjs` | 同源托管专项验证（**18 项**） |

**路径自动探测**：同一份代码在开发态（`apps/server/src/http/`）与构建态（`apps/server/dist/`）
下层级不同，因此按候选列表逐个探测，取第一个含 `index.html` 的目录。
**都找不到也不报错** —— 只提供 `/api`，服务照常可用（纯后端联调场景）。
可用 `WEB_DIST_DIR` 强制指定。

**回退范围只服务"前端路由"**：回退到 `index.html` 只对**无扩展名**的路径生效；
`/assets/xxx.js`、`/favicon.ico`、`/.env` 这类"指名要一个文件"的请求取不到就如实 404。
这一条是 2026-09-18 的独立审查补上的：原先只要不是 `/api` 前缀就一律回退，
于是**构建产物哈希变了 / 资源漏打进镜像时返回的是 200 + 首页 HTML**，
浏览器按 JS 解析直接报 `Unexpected token '<'` —— 正是本模块头注释里写"错误极难定位"的那一类。
（本项目前端没有路由表，单页 + 面板切换，现有路径里没有一个带扩展名，因此收紧不会挡住任何真实路由。）

**契约与业务逻辑零改动**：`packages/contracts`、`packages/teaching`、`apps/web` 均未触碰。

## 六、排查

| 现象 | 原因与处置 |
|---|---|
| 打开域名是**白屏** | 前端产物没打进镜像。检查 `.dockerignore` 是否误排了 `apps/web`；看构建日志有没有 `npm run build` 的输出 |
| 能打开页面但**所有操作报错** | 环境变量没配或配错。看 `/api/health` 的 `modelProvider` 与 `mock` |
| 报 `✗ 模型配置不完整` | 这是**故意的**：缺密钥时服务器主动拒绝启动，不静默降级。按提示补环境变量 |
| 服务能起但**找不到网页目录** | 日志会有 `web.dist.missing`。用 `WEB_DIST_DIR` 指定绝对路径 |
| 中途报"会话不存在" | 服务被缩容重启过（内存会话）。把最小副本数设为 1，或重新开始一次学习 |
| **本地** `npm run build` 报 `Cannot find module @rollup/rollup-win32-x64-msvc` | **已知的环境问题，与本次改动无关**：`node_modules` 里 rollup 的平台二进制丢失（npm 可选依赖的已知缺陷）。修复：删除 `node_modules` 后重新 `npm install`。**容器内是全新安装，不受影响**。（2026-09-18 复核：本机该二进制**已恢复**，`vite build` 实测成功 —— 若你也遇到，先确认 `node_modules/@rollup/` 下有没有 `rollup-win32-x64-msvc`） |
