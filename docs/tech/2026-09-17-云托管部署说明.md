## 二、部署步骤（控制台，约 5 分钟）

### 0. 前置

- 已在腾讯云开发创建环境（地域**上海**，套餐免费体验版即可）
- 本地已确认代码可用（见第四节）

### 1. 打包

在**仓库根目录**执行：

```bash
npm run pack:deploy
```

产出 `deploy-dist/`，并在末尾打印一份**安全检查报告**。
**必须看到「✅ 未发现 node_modules / .git / .env」才能继续** —— 这个目录会被上传到云端。

### 2. 上传

云托管控制台 → **通过本地代码部署**：

| 填写项 | 值 |
|---|---|
| 服务名称 | `calculus-companion` |
| 部署方式 | **上传代码包** |
| 代码包类型 | **文件夹** |
| 选择目录 | 上一步产出的 `deploy-dist/` |
| **端口** | **3000** |

### 3. 环境变量（首次先跑 mock）

在服务的环境变量里加：

```
MODEL_PROVIDER=mock
```

**为什么先填 mock**：第一次部署的重点是验证"管道通不通"（Node 版本、构建、启动），而不是跑真模型。
管道通了再换成 `deepseek` 并补密钥。

验证通过后换成真实通道：

```
MODEL_PROVIDER=deepseek
DEEPSEEK_API_KEY=<你的密钥>
DEEPSEEK_MODEL=deepseek-flash
```

> **密钥填在平台的环境变量里，不是仓库里。** 所以仓库公开也不会泄露，评委也无需配置任何东西。

### 4. 运行模式（重要）

默认的「始终自动扩缩容」**空闲 30 分钟后会缩容到 0** —— 而我们的**会话存在内存里**，
缩容后会话会丢。两种用法：

| 场景 | 最小副本数 | 理由 |
|---|---|---|
| **平时** | **0** | 无流量不产生费用 |
| **演示 / 录屏当天** | **1** | 无冷启动、会话不丢 |

即使保持 0 也能用：评委点开等几秒冷启动，只要**一次性走完流程**（不中断 30 分钟）就不会丢会话。

## 四、本地验证（部署前必须先过）

```bash
npm run typecheck                     # 类型检查
npm run verify:serve-web -w @lc/server  # 同源托管专项，14 项，不消耗额度
npm run verify:all -w @lc/server        # 回归 190 项，不消耗额度
npm run build                           # 构建服务端 + 前端
MODEL_PROVIDER=mock npm run start       # 用构建产物起服务
```

然后浏览器打开 `http://localhost:3000`，应看到学生界面；刷新任意前端路由（如 `/dashboard`）不应 404。

**为什么要有这一步**：本地先证通，云端一旦出问题就能立刻判断是**平台配置**问题而不是**代码**问题。

## 六、排查

| 现象 | 原因与处置 |
|---|---|
| 打开域名是**白屏** | 前端产物没打进镜像。检查 `.dockerignore` 是否误排了 `apps/web`；看构建日志有没有 `npm run build` 的输出 |
| 能打开页面但**所有操作报错** | 环境变量没配或配错。看 `/api/health` 的 `modelProvider` 与 `mock` |
| 报 `✗ 模型配置不完整` | 这是**故意的**：缺密钥时服务器主动拒绝启动，不静默降级。按提示补环境变量 |
| 服务能起但**找不到网页目录** | 日志会有 `web.dist.missing`。用 `WEB_DIST_DIR` 指定绝对路径 |
| 中途报"会话不存在" | 服务被缩容重启过（内存会话）。把最小副本数设为 1，或重新开始一次学习 |
| **本地** `npm run build` 报 `Cannot find module @rollup/rollup-win32-x64-msvc` | **已知的环境问题，与本次改动无关**：`node_modules` 里 rollup 的平台二进制丢失（npm 可选依赖的已知缺陷）。修复：删除 `node_modules` 后重新 `npm install`。**容器内是全新安装，不受影响** |
