## 1 背景与约束

说明书 V2.0 §1.2 明确「不删减 P0 中的符号验证」，§4.4 要求：

- 对导数、切线、单调性相关推导调用符号引擎；
- 验证内容：**求导结果、切线方程、单调区间、极值点**；
- 通过 → 标「已符号验证」；失败 → 标「验证未通过」并触发修正回环；超时 → 标「未验证」，不阻断。

**硬约束（来自 §5.1、§11）**：

1. 单仓库、**单 Web 服务**，Node.js + TypeScript；
2. 在线链接要求「**评委无需配置密钥/环境**」；
3. 现有部署链路（`tsup` 打包 → `node dist/index.js`）不含 Python 运行时。

**由此排除 Python/SymPy 子进程方案**：引入 Python 意味着部署链路要多装一个运行时、多一个版本漂移面，
且与「评委无需配置」的口径直接冲突。初赛只需校验三类课程范围内的结论，不值得为此付部署代价。

## 3 选定方案：mathjs 单依赖

### 3.1 核心设计：结构化断言 + 取样验证，不做通用证明

模型**不直接返回自由文本数学结论**供引擎校验，而是返回**结构化断言**，由教学模块逐类校验：

```ts
type MathClaim =
  | { kind: 'derivative';      expr: string; at: number; claimed: number }
  | { kind: 'tangent';         expr: string; at: number; claimed: string }
  | { kind: 'monotonic';       expr: string; claimed: { inc: [number, number][]; dec: [number, number][] } }
  | { kind: 'extremum';        expr: string; claimed: number[] };
```

**为什么这样设计**：通用代数等价判定是难问题，`mathjs.simplify` 不是判定过程
（对 `sin²+cos²` 之外的一般式可能化简失败）。把输入收敛到「课程范围内的有限题型」，
就能用「**符号求导 + 数值取样**」给出确定结论，而不依赖化简器的完备性。

### 3.2 三类断言的校验算法

| 类型 | 算法 | 依据 |
|---|---|---|
| `derivative` | `math.derivative(expr,'x')` → `evaluate({x: at})` → 与 `claimed` 比对（浮点容差 `1e-9`） | 精确符号求导 + 数值求值 |
| `tangent` | 计算 `f(a) + f'(a)·(x−a)`，与 `claimed` 相减后 `simplify`，判定是否为 `0` | 恒等式两式相减 |
| `monotonic` | 求 `f'(x)`；对 `claimed` 中每个区间**内取 3 个样本点**判 `f'` 符号；再校验分界点 `f'(边界)=0` | **区间取样法**：不需通用求根器，只用求值 |
| `extremum` | 校验 `f'(x)=0` 在声称点成立，且左右邻域符号变化 | 一阶导数变号判据 |

**区间取样法的取舍**：它以「取样正确」替代「区间证明」——理论上可能漏判（如区间内存在未取样的变号点）。
因此加两道补偿：

1. 每区间 **3 个样本点**（端点内侧 + 中点），降低漏判概率；
2. 对 §7.1 的三个**固定案例**保留**硬编码期望值断言**，作为回归基线，任何算法改动都必须仍然通过。

### 3.3 与课程范围的绑定

课程严格限定「导数 / 切线 / 单调性」。**超出该范围的表达式一律不进入符号验证**，
按 §4.4 标「未验证」并如实展示，**不得假装通过**。

## 4 已知限制（如实登记）

1. **非通用 prover**：数学上只覆盖上述四类断言的「课程内形态」，超出即回 `unverified`。
2. **取样法的理论漏判**：见 §3.2 的两道补偿；不宣称「区间级严格证明」。
3. **LaTeX 需转换**：`mathjs` 接受表达式字符串而非 LaTeX。课程范围内符号有限，
   采用**白名单映射表**（`\frac`、`^`、`\cdot`、上下标等）转换；转换失败即标 `unverified`，
   不做猜测性修复。
4. **浮点容差**：数值比对统一 `1e-9`；涉及三角/超越函数的结论在本课程范围内不出现，暂不处理。
5. **验证超时**：`mathjs` 为同步计算，正常在毫秒级；仍设**超时保护**（包裹 `Promise.race` 或
   执行步数上限），超时标 `unverified` 且**不阻断答疑**（§4.4）。

## 5 验证状态类型（建议契约）

```ts
type VerificationStatus =
  | 'symbolic'    // 已符号验证
  | 'human'       // 已人工核验
  | 'unverified'  // 未验证（含超时）
  | 'failed';     // 验证未通过 → 触发修正回环或人工介入
```

六态图谱中的映射（§3.2）：`SUPPLEMENTED → VERIFIED` 仅当 `symbolic` 或 `human`；
`failed` 时转 `DISPUTED`。
