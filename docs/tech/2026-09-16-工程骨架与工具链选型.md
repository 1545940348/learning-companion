## 一、仓库形态：npm workspaces 单仓库

```
apps/web           React + TypeScript    交互层（A）
apps/server        Node.js + TypeScript  模型适配 / 会话 / 接口（C）
packages/teaching  独立 TS 模块          提示词 / 依赖 / 补充 / 校验 / 题目（B）
packages/contracts 共享类型与契约        前后端唯一事实来源（C）
```

**为什么用 npm workspaces 而不是 pnpm**：npm 随 Node 自带，三人环境无需额外安装，排查问题成本最低。10 天工期下，工具链的确定性比安装速度更重要。

**为什么 contracts 与 teaching 直接对外暴露 TS 源码**（`main` 指向 `src/index.ts`，不做 build）：

- Vite 与 tsx 都能直接编译 TS，省掉一层构建与监听；
- B 修改 `packages/teaching` 后服务端立即生效，不需要手动 rebuild；
- 代价：生产构建需由打包器处理（server 用 tsup，web 用 Vite），已在 `package.json` 中配好。

**Vite 的额外处理**：workspace 包在 `node_modules` 中是软链接，Vite 默认可能跳过对其转译。因此 `apps/web/vite.config.ts` 用 `resolve.alias` 把 `@lc/contracts` 直接指向源码路径，消除歧义。

## 二、服务端选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Express 4 | 生态最普及，三人可读改；五个接口规模下性能不是瓶颈 |

### 冒烟测试发现并修复的设计缺陷

零材料提问被来源校验拦截：

```
UNAUTHORIZED_CONTENT: AI 补充内容未经学生授权
```

**原因**：零材料回答的 `sourceType` 为 `ai-supplement`，而校验规则要求它必须绑定已授权来源；轻路径下没有任何来源，因此必然被拒。

**这是真实的规则冲突，不是 mock 的问题**——真实模型在零材料场景同样会产生 `ai-supplement` 块。

**修复**：为 `validateAnswerBlocks` 增加 `requireAuthorization` 选项。

- 材料路径：`true`，模型不得凭空引入材料外内容（保护用例 E7）；
- 轻路径：`false`，学生主动提问即视为授权使用通用知识，此时由 `basedOnMaterial === false` 承担"未基于你的材料"的标注责任（说明书 2.1）。

## 六、环境问题记录（Windows 开发环境）

### 1. npm 必须指定项目内缓存目录

沙箱 / 受限环境下，npm 写用户缓存目录（`AppData`）会被拦截，表现为**命令静默终止、无任何输出**。修复：

```bash
npm install --cache ./.npm-cache
```

`.npm-cache/` 已加入 `.gitignore`。

### 2. rollup 平台可选依赖缺失导致 `vite build` 失败

```
Error: Cannot find module @rollup/rollup-win32-x64-msvc
```

**原因**：首次 `npm install` 被中断，留下不完整的 `node_modules`，npm 误判可选依赖已满足（npm 已知问题，cli#4828）。

**修复**（Windows）：

```bash
npm install --no-save @rollup/rollup-win32-x64-msvc
```

**注意**：不要把它写进 `package.json` — 平台绑定依赖会让 macOS / Linux 队友安装失败。彻底解法是删除 `node_modules` 与 `package-lock.json` 后重装。

**影响范围**：只影响 `vite build`（生产构建）。`npm run dev` 走 esbuild，不受影响。

### 3. 工作区 `.git` 目录被环境锁定，导致无法提交

**现象**：`git add` 报 `fatal: unable to write new index file`。进一步验证发现 `.git` 目录**连创建文件都被拒绝**：

```
[FAIL] 在 .git 中创建新文件: [Errno 13] Permission denied
[FAIL] index 改名: [WinError 5] 拒绝访问
```

目录权限模式正常（`0o40777`），`chmod` 无效，说明不是文件权限问题，而是环境层面对该目录的句柄锁定。

**已尝试且无效的方案**：

| 方案 | 结果 |
|---|---|
| 删除残留 `.git/index.lock`（某次操作中断遗留） | 锁被清除，但写入仍失败 |
| 删除并重建 index（`git read-tree HEAD`） | 同上 |
| `GIT_INDEX_FILE` 指向独立索引 | 部分成功，但索引不完整 |
| `GIT_DIR` + `GIT_WORK_TREE` 指向新克隆的 `.git` | `git status` 正常，`git add -A` 仍失败 |
| 分批 `git add` | 首批（`apps`）成功，后续全部失败 |
| 重试 8 次 | 全部失败 |

**结论**：本环境下 git 写入不可靠，**提交需在本地终端手动执行**：

```bash
cd D:\smallbox\Projects\LearnBuddy
git add -A
git commit -m "feat: 搭建前后端骨架（契约、教学模块、服务端、前端）"
git push
```

**若本地终端也失败**，排查是否有进程持有 `.git` 句柄（编辑器 git 集成 / 文件同步 / 安全软件），关闭后重试。

**若 `git add -A` 失败**，改分批：

```bash
git add apps packages docs package.json package-lock.json tsconfig.base.json .gitignore README.md
git rm --cached .env.example
```
