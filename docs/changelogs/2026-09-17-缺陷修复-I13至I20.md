## 2 逐条修复

### 2.1 `I13`（P0，已修）—— 有会话但零材料时提问被误判 403

**先复现，再改。** 用交接给的命令，实测两分支：

```
POST /api/session                                   → 201
POST /api/tutor {sessionId:<该 id>, materialVersion:0, question:"单调性怎么判断", mode:"explain"}
                                                    → 403 {"code":"UNAUTHORIZED_CONTENT", "retryable":false}
POST /api/tutor {sessionId:null, ...同一条问题}      → 200
```

**根因**：`apps/server/src/http/routes.ts` 的 `/tutor` 里
`requireAuthorization: sessionId !== null` —— 判据是**会话是否存在**，
而语义（`packages/teaching/src/validate.ts` 的注释）是「**材料路径**下为 true」。
点「开始新学习」或「按我的材料出题」都会建会话但材料为空 → 走"材料路径"的严格校验 →
mock/模型给的 `ai-supplement` 块无授权引用 → 403 且不可重试。

**改法**：

```ts
// 改前：requireAuthorization: sessionId !== null
const requireAuthorization = materials.length > 0;
```

⚠️ **一处需要说清的细节**：此作用域里的 `materials` 是 `toSlices(session)` 的返回值 ——
**它是「学生材料 + 已授权补充块」的切片列表**，与 `allowedRefs` 同为空／非空。
因此判据的实际含义是「**本次请求是否真的带了可引用的来源**」，而不是字面的"学生材料数 > 0"。
这两者在**今天**等价（补充块不可能先于材料出现，`/api/gap` 需要图谱、图谱需要材料）；
但若将来允许"只有补充块"的会话，语义会分叉 —— **已在代码注释里写明这一点，不再靠读者推断**。

**验证**：同一条请求 **403 → 200**，`scope=derivable`、`basedOnMaterial=false`、`blocks=1`。
另加 2 项 `verify:flow` 断言（`⑬`）专门走这条路径。

### 2.2 `I14`（P1，已修）—— 被拒块被静默丢弃

原实现只在 `valid.length === 0 && rejected.length > 0` 时报错，有块通过时被拒块无声消失。

- **契约**：`TutorResponse` 加性新增可选字段 `droppedBlocks?: {count, reasons[]}`
  —— 契约变更记录见 `tech/2026-09-17-契约变更-TutorResponse-droppedBlocks.md`
- **服务端**：只在"部分被丢弃"时填入；全部被拒仍走 403（不返回该字段）
- **前端**：`TutorPanel` 显示「本次回答不完整：另有 N 段内容没有展示 —— 未通过来源校验（原因）」

**取舍**：选"加字段"而非"降级为标注块"。被拒块之所以被拒，正是**它的来源声明不成立** ——
给它挑一个 `sourceType` 塞回 `blocks[]` 就是在替它做一个已被驳回的声明；只带一句"某段被拦下"
又不成其为 `AnswerBlock`。

**⚠️ 跨所有权**：`apps/web/src/components/TutorPanel.tsx` 是 **A 的工件**，本轮代改 →
**已标注并请 A 复核**。只加字段不渲染等于"换个地方继续静默"，所以渲染侧不能不做。
