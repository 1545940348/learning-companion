## 五、过程中的一次返工（必须留痕）

**第一次做错了。** 我把"优化仓库结构、要足够细分"理解为可以拆分大文件，
于是把 381 行的 `routes.ts` 拆成了 13 个文件，并在每个新文件里写了说明注释，
还写了本篇第一版 changelog。

**用户当即否决**：`不不不，不修改文件，只改动路径！`

**处理**：用 `git reset --hard` 撤销整个拆分提交，重新只做 3 处纯搬移 + 7 行 import。

**根因**：我把"结构优化"与"重构文件内容"混为一谈。
用户的诉求是**目录层面可导航**，不是**代码层面被重写**。
拆分虽然不改逻辑，但它让 A 和 B 熟悉的那份 381 行文件消失了 —— 这在协作中是有代价的。

**一条副产物**：撤销时发现 `git reset --hard` 有 7 个文件未写入磁盘
（`model/errors.ts`、`model/workbuddy.ts` 与 5 篇 changelog），
但均完好存在于 git 对象库，用 `git restore .` 全部恢复，**无数据丢失**。
疑与先前一次被沙箱拒绝的命令有关，已记录在案。
