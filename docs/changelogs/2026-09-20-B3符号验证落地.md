四类断言逐条核验，**不做通用证明**（选型文档 §3.1 的类型、§3.2 的算法）：

| 断言 | 判据 |
|---|---|

| `tangent` | 由 `f(a) + f′(a)(x−a)` 与断言式**相减**，**`rationalize` 的系数向量全零 ⟺ 恒等** |

汇总口径**从严**：任一条 `failed` → 整体 `failed`；全部 `verified` → `symbolic`；

## 二、落地时踩到并纠正的四处（都有实测证据）

### 坑 1 ｜ `mathjs` 的 `derivative()` 对垃圾输入**静默返回 0**

```
derivative('not-an-expr', 'x') => 0
derivative('x^2', 'y')         => 0
```

⇒ **"表达式没被理解"会伪装成一个看起来合理的结论**。这条决定了架构：
**挡住它的只能是白名单**（`latex.ts`），必须在进引擎之前拒掉。
回归里 F10 就是这个陷阱的定点断言（`y^2` 必须被拦）。

### 坑 2 ｜ `simplify()` **不是判定过程** —— 选型文档 §3.2 的算法照抄会产生**假红**

```
simplify('1 + 2*(x-1) - (2*x-1)')          => 0            ← 原始案例能过
simplify('(x+1)^2 - x^2 - 2*x - 1')        => (x + 1) ^ 2 - 2 * x - (x ^ 2 + 1)   ← 恒等式却没归零
```

⇒ 改用 **`rationalize(expr, {}, true)` 的系数向量**：

```
rationalize('(x+1)^2 - x^2 - 2*x - 1') => coefficients: [0,0,0]    ← 精确
```

**在多项式范围内这是完备判定**（不是取样）。`simplify` 只作非多项式时的退路，且退路判不了时
**标 `unverified` 并写明"未据以判定"**，不硬判。

### 坑 3 ｜ 求值会返回**复数或 `Infinity`**

```
evaluate('sqrt(x)', {x:-1})  => Complex {re:0, im:1}
evaluate('x^0.5',  {x:-1})   => Complex
evaluate('1/x',    {x:0})    => Infinity
```

⇒ 一律按"**定不了**"处理（`unverified`），**不得当成通过，也不得当成"错"**（后者会让模型背锅）。

### 坑 4 ｜ 提示词快照脚本少做了一步**模板转义还原**

`check-prompts.mjs` 比对的是**源码原文**，而模板字面量里的 `\\frac` 在运行时是 `\frac`。
之前所有提示词都不含转义，所以一直没暴露。`B3` 要在提示词里写白名单命令，于是两条路都堵：
文档照"最终文本"写 `\frac` → 比对失败；照源码写 `\\frac` → **文档不再等于送给模型的内容**。

⇒ **改脚本**（不是改文档迁就脚本）：加 `unescapeTemplate()`，把 `\\`/`\n`/`\t`/`\r`/`` \` ``/`\$`/引号还原，
使比对对象**等于运行时字符串**——这正是该脚本自己写的用途（"评审要看的是最终文本"）。
**这是本轮唯一一处"改检查工具"的改动**，理由与证据如上；改完 6 个常量全部逐字一致。

### 另有一处环境性阻断（不是代码问题）

`npm install` **写不了已有的 `package.json` / `package-lock.json`**，三条通道全部被拦：

| 通道 | 结果 |
|---|---|
| 沙箱内 `npm install mathjs -w @lc/teaching` | ❌ `EPERM: open 'packages/teaching/package.json'` |
| **绕沙箱**重跑（用户授权） | ❌ `[safe-delete] 操作失败: genie-trash … ETIMEDOUT`（reify 被钩子拦下） |
| `--package-lock-only`（跳过 reify） | ❌ 仍 `EPERM: open 'package-lock.json'` |

**实际后果**：`node_modules/mathjs` 装上了、`packages/teaching/package.json` 已用宿主工具补上声明
（**这两件是本轮必需的**），但**锁文件没动**。
⇒ `npm ci` 的机器会漏装 `mathjs`；`npm install` 正常；容器 Dockerfile 本就 `rm -f package-lock.json` 再装，不受影响。
**如实登记，不掩盖**：并入 `I39`，需在一台 npm 可写的机器上跑一次 `npm install` 收尾。

## 三、被否决 / 被修改的真实记录

| 卡 0-4 的 JSON 契约落点 | "`SYSTEM_KNOWLEDGE` 的 schema 加 `edges`"（读起来是顶层） | **改为 `parsed.graph.edges`**：`buildGraph()` 读的是 `parsed.graph`，照顶层写会**静默无边、不报错** |

| 选型文档 §3.2 的切线判据 | "相减后 `simplify` 判 0" | **改为 `rationalize` 系数全零**（见坑 2：`simplify` 有真实漏判） |

| `I18` 的 DISPUTED 断言 | 卡片建议"`failed` 才能 DISPUTED" | **不加**：§3.2 允许"来源冲突"触发 DISPUTED 而未必 `failed`，那样写会挡住合法路径。只把**规则原文明确**的那条焊死 |
| `I15` 的"反查概念名" | 卡片："从 `session.graph` 反查 `KnowledgePoint.name`" | **按卡片实现，但如实说明它现在通常查不到**：图谱节点只由 `points[]` 构成，而要补的是 `prerequisites[]` 里的前置概念。**不编造名字**，退回 `conceptId`。完整修复的岔路并入 `I42` |

## 五、如实声明的边界（不得当成"已完全实现"）

1. **真实通道未实测**：真实模型是否按新 schema 返回 `claims`，本轮**没有验证**（回归与演示全走 mock）。
   若返回自由文本，`supplementGap` 会把原文当正文、`claims` 记空 → 如实落 `unverified`。

3. **单调性是取样法**，**不做区间级严格证明** —— 理论上可能漏判（区间内未取样的变号点）。
   两道补偿：每区间 3 个样本点 + `FIXED_CASES` 固定基线。

5. **`I15` 只部分收口**（见上表）。
6. **锁文件未同步**（`I39`）。
7. **产物体积**：`apps/server/dist/index.js` **87 KB → 1.53 MB**（`mathjs` 被 esbuild 内联）。
   这是**有意的取舍**：换来自足可跑的产物（`verify:dist` 的前提，也是 `B1` 的教训）。
