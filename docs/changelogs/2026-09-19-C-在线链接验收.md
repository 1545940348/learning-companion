## 3. 线上快照落后多少

`/api/health` 自报 `build: { mode: 'dist', entry: 'index.js', builtAt: '2026-09-18T10:29:07.000Z' }`。

- `builtAt` 是**产物文件的 mtime**（= 镜像构建时刻），**不是源码版本**，所以它不能用来判断"跑的是哪一版代码"；
- 真正可判定的是**行为**：`/nope.webmanifest` 与 `/assets/` 两处按 `I22` 修复后的代码应为 `404`，
  实测为 `200` → **镜像源码快照早于 `7cc1c78`（"修复 I22–I27 六项缺陷"）**。
- 已知 PR 情况：#9（同源托管）、#10（`I22`–`I28`）、#11（锁文件与打包排除）。线上大约停在 **#9 之后、#10 之前**。

## 5. 一个待人工确认的响应头

线上 `/`、`/api/health`、404 响应里都带 `content-disposition: attachment`，且 `last-modified`
被拼成两个值（`<现在>,<文件 mtime>`）。核查：

- 仓库代码**没有任何地方设置**该头（`grep -rn disposition apps packages scripts` → 空）；
- 同机 `curl` 访问 `example.com` / `baidu.com` / `szu.edu.cn` **都没有**该头（即不是本机代理对所有站点都加）;
- `server: cbrgw` 是 CloudBase 网关的标识。

⇒ **要么是 CloudBase 网关对我方域名的策略，要么是本机代理对该域名的特殊处理**，本机无法区分。
**风险**：若浏览器真的收到 `Content-Disposition: attachment`，点开链接会**下载** `index.html` 而不是显示页面 —— 演示当天会直接失败。
**处置**：请**用真实浏览器打开一次链接**确认页面正常渲染（本环境无法安装 `agent-browser`，见 `I8`）。
若确认是下载 → 记为阻断项，优先排查平台域名配置。
