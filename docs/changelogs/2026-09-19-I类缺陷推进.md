## 2. 逐条处置

### `I29` + `I31`：零材料 + 已授权补充块 → 403（**拍板：修 mock 保真，不放宽判据**）

- **根因**：`mockTutor` 只接收 `materialIds`，**完全忽略 `supplementIds`** → 只要"没有学生材料、但有已授权补充块"，mock 恒返回**无引用**的 `ai-supplement` 块 → 被来源守卫拒（403 且 `retryable=false`）。
- **为什么不改守卫**：守卫的语义是「回答必须能追溯到**真实存在**的来源，无引用即拒」—— 这是防线本身的定义。把"无引用也收"当修法，等于接受无法核对来源的内容（真实性红线）。
- **改动**：`mockTutor(materialIds, supplementIds)`；无学生材料时引用**已授权的补充块**并把 `sourceType` 标对；文案分三支（有材料／只有补充块／纯通用知识），第三支明说「不是你的讲义原文」。
- **证据（红/绿）**：复现脚本 `.learnbuddy/repro-2026-09-18/zero-material-supplement.mjs` 第 ③ 步 **403 → 200**，且 `citations[0].refId === supplementBlockId`。
- **断言**：`verify:flow` 补 4 项（⑮）——原 36 项**没有任何一条**经过这条路径。

### `I30`：`/api/quiz` 与 `/api/tutor` 判据"相反"（**拍板：不改契约，只统一文案**）

- **判据不变的理由**：两者回答的是**两个不同问题**。`/api/tutor` 问「有没有可引用的来源」（学生材料 **或** 已授权补充块）；`/api/quiz` 问「有没有**学生自己的材料**」，因为返回的题必须标 `source: 'material'`，而 `QuizSource` 只有 `'fixed' | 'material'` —— 拿补充块出的题标 `'material'` 就是**新的真实性红线**（加取值属契约变更，牵动 A/B，本轮不引）。
- **改动**：会话里只有补充块时，400 文案明说「这个会话里只有 N 段 AI 补充内容，没有你自己的讲义……」（原先笼统"还没有材料"，会让学生以为会话是空的，去翻一个其实有内容的会话）。
- **断言**：`verify:flow` ⑯（1 项）。

### `I17`：`health.version` 硬编码（**拍板：运行时读包版本，取不到报 null**）

- 原先硬编码 `'0.2.0'`，而五个 `package.json` 都是 `0.1.0` —— 全仓无 `0.2.0` 出处，评委对照源码仓库会先看到这个对不上的数字。
- 新增 `describeVersion()`（`config/build-info.ts`）：按四个候选位置探测 `@lc/server` 的 `package.json`，**取不到即 `null`**（与 `build.builtAt` 同一思路：不编一个看起来合理的值）；刻意**不做**"找不到就退回硬编码"的兜底 —— 那等于把同一个失真换个地方藏起来。
- **契约变更**：`HealthResponse.version: string → string | null`。已核对消费方：`apps/web` **不读**该字段（界面不展示版本号），无调用点受影响。
- **断言**：`verify:flow` ⑰（1 项）——与脚本直接读取的 `package.json` 版本比对。

### `I36`（本轮新登记）：`basedOnMaterial` 把「只有 AI 补充内容」报成「基于你的材料」

- 契约语义是「是否基于**学生材料**；轻路径为 false」，而实现链上算的是 `toSlices()`（**含**已授权补充块）：`tasks.ts:410` 按 `input.materials.length > 0` 算，`routes.ts` 直接透传 → "点过补缺口、但没交讲义"的会话被标成基于材料，界面据此显示「基于你的材料」。
- **改动**：路由层按会话重算 `basedOnMaterial = session.materials.length > 0`。
- 顺带记录：mock 自报的 `basedOnMaterial` **从来不被采用**（教学层会重算），`I31` 里对该字段的改动只是"顺手对齐语义"，不产生行为。

### `I21`：两处字面 `**`（JSX 不处理 Markdown）

- `ProfilePanel.tsx`、`QuizPanel.tsx` 的 `**…**` 改为「」。**同步核查了两条依赖这些字符串的既有断言**：它们用的是**不含 `**` 的子串**，故改动后仍有效；若当初写成含 `**` 的整串，这次改动会让断言**静默变成永假**。

### `I34`：图谱节点永久「未判定」

- **根因**：`nodeStatus` 只在 `gaps[node.id]` 与 `prerequisites[].conceptId` 里找，而生成数据是 `points[].id = 'kp-monotonicity'` vs `prerequisites[].conceptId = 'kp-derivative'` —— **两个不同的东西**（前者是"这里有什么"，后者是"学这个之前需要什么"），从不重叠 → 恒 `null`。
- **改动**：增补第三个来源 —— `points[].id === nodeId` 且 **`citations` 非空** → `LOCAL`。**只在有引用时才判 `LOCAL`**：没有引用仍标「未判定」，不把"模型没给引用"说成"材料未覆盖"（那也是一次它没做过的判定）。
- **配套**：`mockKnowledge` 改为如实带上材料引用（否则这条修复在演示里看不到效果）。
- **为什么以前的断言是绿的**：`verify:render` 的 4d 用例把节点 id 与 conceptId **手工对齐**了，而生成器从不产生这种数据 → **锁不住真实场景**。本轮新增 **4e**（真实 id 形态 + 无引用反例）。
- ⚠️ 仍**无浏览器验证**（`I8`）：图谱实际渲染效果需人工看一眼。

### `I35`：`I14` 的提示条把内部 refId 渲染给学生（**选服务端改写**）

- 契约对 `droppedBlocks.reasons` 的定位本就是"给学生看的说明"，就该由产出方保证可读；前端截断是"按形态猜"，文案一变就静默失效。
- 改动：`routes.ts` 加 `toStudentReason()`（三类前缀 + 兜底），并把原始原因（含 refId）记入 `tutor.blocks.dropped` 日志。
- **未触碰 `packages/teaching`（B 的工件）**。既有断言用的是不含 id 的那条 reason，故不受影响。
