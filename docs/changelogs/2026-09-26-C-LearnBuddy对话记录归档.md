## 二、为什么需要这么一轮

赛事手册 §4.1 把「LearnBuddy 使用记录」列为**必需**提交项，并直接对应 25% 的
「AI 工具使用」评分；手册同时自述"未明确格式与颗粒度"。而团队另有硬规矩
「**不得事后补造**」（初赛补充说明 §6.2）。

两条要求叠加后的唯一安全解是：**只交出平台自己写下的原始日志，并把"可核验"做成硬证据**。
这也是本脚本存在的全部理由 —— 它不调模型、不做摘要，"整个流程可被任何人在本仓库重跑复现"。

## 四、本轮发现并如实登记的三件事

### 4.1 🔴 原始日志里含一段**真实凭据**（已脱敏，但须知道它存在）

- 位置：`09e33b85-…jsonl` L65（2026-09-21 18:50 排查 GitHub 连通性的那次会话）。
- 成因：为查"为什么 `github.com:443` 不通"，跑了一句 `env | grep -i proxy`，
  把环境变量整段打印进日志，其中含 `CODEBUDDY_MCP_CONFIG` 里的
  **`Authorization: Bearer <本地连接代理会话令牌>`**（目标为 `127.0.0.1` 本机端口，**泄漏面很小**，
  但性质是凭据）。
- 处置：导出时按确定性规则替换为占位符；**已用仓库自己的 `npm run verify:sensitive` 验收**
  （工作区 ＋ 全历史，**17 项通过 / 0 失败**），并额外对 PDF 做了二进制抽查（PDF 不在该脚本的扫描范围内）。
- 连带发现：全量扫描其余命中**均为假阳性** —— 测试占位密钥、只有变量名没有值、
  以及 2072 处 40 位十六进制串（实为 **git 提交号**）。**没有第二个真密钥。**
- ⚠️ **给后续会话的提醒**：`env | grep` 这类命令会把整段环境变量写进对话日志，而对话日志是提交材料。
  以后排查环境问题**不要整段打印环境变量**。

### 4.2 09-24 **全天没有对话记录**（断档，已登记，不回填）

导出后逐日统计发现：09-23 23:33 之后直到 09-25 21:53 之间**没有任何会话**。
该断档已写进主文档 §2.3 与 `records/README.md` §五，并用一句话说明
"没有记录就只能登记为没有记录，不做回填或推测"。

## 五、AI 产出被修改 / 被纠正的真实记录

| # | AI 初版产出 | 问题 | 改正 |

| 1 | 脱敏只套在"工具动作摘要"上 | **提问与 AI 回复未过滤** —— 真令牌若出现在这两处会直接漏出去 | 三处统一在**入库前**脱敏 |
