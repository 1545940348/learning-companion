## 二、为什么这样改

**1. 仓库此前只有文档，没有可构建的代码。** 说明书排期第 1 天要求 C 完成"冻结契约＋验证 API 与部署"，
而契约的落地形态是 `packages/contracts`，因此先建立最小可构建骨架，而不是先写页面或先写服务。

**2. 模型调用必须按平台给定方式接入。** 原先 `.env.example` 预设了 HTTP 端点与固定模型名，
但实测表明：认证由 SDK 读取环境变量完成，且模型名由上游按输入类型自动选择。
继续保留 `MODEL_BASE_URL` / `MODEL_NAME` 会误导后续开发者去"填一个不存在的地址"。

**3. 适配层的边界是为了让 B 能独立开发。** 说明书 7.2 规定 B 通过 C 注入的模型函数运行。
因此适配层对外只暴露 `@calc/contracts` 的 `ModelClient`，SDK 类型不外泄——
将来更换调用方式不应导致 B 的代码变化。

## 三、关键实现约束（均来自说明书，非自行发挥）

| 约束 | 实现 | 依据 |
|---|---|---|
| 禁用工具执行 | `tools: []` + `canUseTool` 一律 deny | 教学运行时只读；测试代码已验证可行 |
| 不持久化 | `persistSession: false`、`maxTurns: 1` | 会话由服务端按 5.3 自行维护，不依赖 SDK 会话 |
| 不加载外部配置 | `settingSources: []`、`mcpServers: {}` | 避免宿主配置影响教学运行 |
| 60 秒超时 | `AbortController` + `MODEL_TIMEOUT_MS` | 说明书 5.3 |
| 图片上限 5MB、仅 PNG/JPEG | 按文件头判断格式，不信任扩展名 | 说明书 2.1 |
| 密钥不泄露 | `redact()` 双重保险，错误详情脱敏 | 参赛提交含对话记录，密钥不得外流 |
| 隔离宿主凭证 | 显式清空 `CODEBUDDY_AUTH_TOKEN` / `BASE_URL` / `CUSTOM_HEADERS` / `MODEL` | 防止宿主配置"看似生效、实际被遮蔽" |
