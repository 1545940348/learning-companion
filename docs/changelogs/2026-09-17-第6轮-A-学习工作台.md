## 5 本轮**发现的问题（交 C）**

### 5.1 构建产物无法启动 —— 属部署阻断项

`npm run build` 成功后执行 `node dist/index.js` 直接崩溃：

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module
  '.../packages/contracts/src/session.js' imported from '.../packages/contracts/src/index.ts'
```

原因：`packages/contracts` 的 `exports` 指向 **TS 源码** `./src/index.ts`，源码内部用
`./session.js` 这类 ESM 后缀互相引用。`tsx` 能把 `.js` 映射回 `.ts`，**原生 node 不能**；
而 `tsup` 又默认把 workspace 包当 external，于是产物里留下了这条无法解析的导入。

影响：**C7 部署**（在线链接）会直接失败。修法二选一：
① tsup 加 `--no-external @lc/contracts @lc/teaching` 把两个包打进产物；
② 给两个包加真正的构建步骤并让 `exports` 指向 `dist`。
（本轮用 `tsx` 启动绕过，仅限本地开发。）

### 5.2 契约冗余：`ProfileEvent.sessionId` 在请求侧是多余的

`POST /api/profile` 的请求里，每个事件都要带 `sessionId`，
但服务端 `guardProfileEvents(raw, sessionId)` 会用请求级 `sessionId` **覆盖**它。
建议契约细化出 `ProfileEventInput`（不含 `sessionId`）。
A 侧已把冗余收敛在 `useWorkbench` 的 `withSessionId()` 一处，改动成本仅一处。

### 5.3 契约缺口：材料「替换」语义 —— 用例 E12 无法完整实现

`POST /api/knowledge` 只支持**追加**材料，没有"替换某一份"的字段。
因此「就地纠错」目前是：把修正文本作为**新材料**提交并重建图谱，
旧文本仍留在会话材料集中（前端标记为「已修正」）。
E12 要求的"重建受影响的知识点"达成，但"旧文本参与解析"这一副作用无法消除。
