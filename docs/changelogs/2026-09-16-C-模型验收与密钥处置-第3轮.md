## 二、密钥误置事件（必须留痕）

**经过**：C 指示用户"把密钥填进 `.env`"，但当时 `.env` **并不存在**（仓库中只有 `.env.example`）。
用户因此把**真实密钥填进了 `.env.example`** —— 而该文件被 git 跟踪、会随仓库提交。

**这是 C 的指令缺陷，不是用户的失误。** 给非技术用户下密钥指令时，未先确认目标文件是否存在。

**泄漏范围核查（结论：无泄漏）**：

| 核查项 | 结果 |
|---|---|
| HEAD 提交版本中各变量值 | 全部为空 |
| 是否有改动被暂存（staged） | 无 |
| `git log --all -p` 扫描密钥形态 | **0 行命中** |
| `.env` 是否被 gitignore 覆盖 | 是（第 14 行） |

→ 密钥从未进入 git 历史，**无需更换密钥**。

**处置**：`cp .env.example .env` 将配置整体搬入受忽略的 `.env`，再以 `sed` 清空 `.env.example` 的值。

**顺序刻意安排**：先清空、后读取。因为**这段 LearnBuddy 对话记录是参赛提交材料**，
若先打开该文件，密钥会随之进入提交物。全程未读取、未打印密钥内容。

**已写入记忆的教训**：涉及密钥的配置操作，第一步先确认目标文件是否会被提交；
给非技术用户下指令前，先确认目标文件已存在或代为创建。

## 四、被推翻的判断（本轮最重要的技术结论）

第 2 轮的 changelog 与 `docs/tech` 原稿均记载"结构化输出支持"，依据是 SDK 导出了
`OutputFormat` / `JsonSchemaOutputFormat` 类型。

**实测两次（横跨两个模型）后推翻**：传入 `options.outputFormat` 后
`ResultMessage.structured_output` **均未返回**，模型照旧输出 markdown 散文，
自填的 enum 取值也超出允许范围。

**可用替代路径已验证**：在提示词中明确要求"只输出 JSON"后，模型返回
`{"answer": 2, "sourceKind": "derived"}` —— 干净纯 JSON、无 markdown 包裹、enum 被遵守。

**对 B 的直接影响**：B4 三类来源校验**不能依赖 `structured_output`**，
必须自建"提示词要求 JSON ＋ 解析 ＋ 校验 ＋ 重试"。工作量与风险均上升，
E7（假引用不得作为正常答案展示）仍然可做，但依赖解析器与重试逻辑的正确性。

**行动**：需尽早同步给 B，避免其按错误的实现前提开工。

## 五、附带发现

**模型名由上游动态分配，且会变。** 同一份代码、同一天三次实测得到三组不同结果：

| 时刻 | 输入 | 模型 |
|---|---|---|
| 18:42 | 纯文字 / 含图片 | `hy3` / `hy4-preview-f` |
| 19:05 | 纯文字 / 含图片 | `glm-5.3` / `glm-5.3-flash` |
| 19:14 | 纯文字 | `minimax-m3` |

影响：PPT 与视频**不得写死模型型号**；演示当天的回答风格与速度可能与开发时不同；
固定题答案一致性与"同一问题两次回答是否稳定"需额外核验。

**额度口径仍未知**：`total_cost_usd` 三次均报 0，本环境不提供成本数据。
但已取得 token 实测值，其中**含图片约 699 入，是纯文字（70 入）的约 10 倍** —— 额度规划须将图片路径单列。
