## 2 修了什么（逐条）

### 2.1 `I22` · SPA 回退守卫的三个漏口（P1，真实性红线同类）

判定用的是**未解码**的 `req.path`、扩展名正则带 `{1,8}` 上限、结尾带斜杠的目录式请求
也没被排除 —— 三者都会让"取不到的资源"返回 **200 + 首页 HTML**，
正是这道守卫被加进来要防的失效。

**改法**：先解码再判（仅用于分类，不用于拼路径）；只看**最后一段**是否含点（不限长度）；
`/` 以外结尾带斜杠的一律不算前端路由；解码失败（`%zz`）**倒向严格一侧**；
`req.path` 与解码后路径**都**判一次 `/api`（`/api%2Funknown` 原值不以 `/api/` 开头）。

**证据**：`.learnbuddy/swfix/probe.mjs` 同一组探针 —— 旧模块 **7 项失败**、新模块 **15/15**。

### 2.2 `I23` · 产物在运行期消失时是 500，应为 404（P2）

`npm run build:clean` 会把 `apps/web/dist` 挪走，整个重建窗口内页面全是
`500 INTERNAL` + error 级 `http.unhandled` 日志 —— 把"正在重建"报成"服务端故障"。

**改法**：模块内区分 `ENOENT`/`ENOTDIR`/`ENAMETOOLONG` → **404** + warn 级
`web.index.missing`；其余错误仍交统一错误处理。**实测旧模块 500、新模块 404。**

### 2.3 `I24` · 一条**恒真断言**（P2，治理）

`typeof result.mounted === 'boolean' && result.webDistDir !== undefined` 恒成立 ——
把 `candidateWebDistDirs()` 改成 `return []`，脚本仍然全绿，而那个函数决定了
容器里**能不能提供页面**。

**改法**：拆成两条 —— ① 返回值必须自洽（挂载⇒目录里真有 `index.html`；未挂载⇒`null`）；
② **独立重算**候选表再比对（不 import 模块里的函数，否则两边一起变空、断言又恒真）。
**实测**：清空候选表 → 新断言报红（27/1）；还原 → 28/0。

### 2.4 `I25` · `pack-deploy.mjs` 对输出目录没有身份校验（P1，会删库）

`PACK_DEPLOY_OUT` 是唯一由用户提供的路径，而脚本对它**没有任何校验**：

- 输出目录 = 仓库根（或它的上级）→ `prepareOutDir()` 先 `rm(dir, {recursive:true, force:true})`，**等于删库**；
- 输出目录在仓库内部且名字不在 `EXCLUDE_DIRS` → `copyTree` 先建目标再 `readdir` 源，
  每层都能看见自己 → **无限自嵌套**（上一轮两次复现：819 层 / 473 MB）。

**改法**：`assertUsableOutDir()`，在**任何删除动作之前**拒掉这两种路径，宁可拒跑。
**实测 4 个用例**（=仓库根 / 仓库内未排除名 / 仓库的上级 → 全拒并 exit 1；
默认与首层被排除 → 正常）；拒后夹具完好。

### 2.5 `I26` · 排除名单是 `.gitignore` 的手抄子集，且自检与拷贝不同源（P1，会泄密钥）

`EXCLUDE_FILES` 只有 4 个精确名字、自检用的 `FORBIDDEN_NAMES` 更只认 `.env`/`.env.local`：
`.env.bak`（被 `.gitignore` 的 `.env.*` 覆盖，所以 `git status` 是干净的）、`secrets.json`、
`service-key.pem` 会被**照拷进上传包**，而末尾**仍打印「✅ 可以上传」**。

**改法**：收敛为**一份**规则 `isForbiddenFile()`，`shouldCopy()` 与 `scan()` 共用，
覆盖 `.gitignore` 全集（`.env` / `.env.*` / `*.pem` / `*.key` / `*.p12` / `secrets.json`），
例外 `.env.example`。

**红/绿实测**：旧脚本产物 **8 个文件**（含三个密钥文件）且打印 ✅；新脚本 **5 个**、零泄漏；
**真实仓库 152 文件 / 1.53 MB ✅**（未误伤）。

### 2.6 `I27` · 计数会随环境漂移（P2，文档口径）

`warn()` 只累加 `warned`、不计入 `passed`，而 4 处是 `ok()`/`warn()` 二选一 ——
其中"本机存在 `.env`"那处恰好由**照 `.env.example` 的说明做真实通道联调**触发：
**按文档做事反而让计数少 1**（`sensitive` 15→14、`repo` 33→32）。

**改法**：`warn()` 也计入 `passed`（它是一条**已完成**的检查），汇总改为"N 项通过（其中 M 项注意）"。
**实测同一 warn 分支下：旧 13、新 15。**
