## 1 一句话定位

一个帮大学生读懂微积分讲义的**教学助手**：回答问题之前，先检查学生上传的讲义里
**有没有解释这个问题所依赖的前置概念**；发现缺口时，**由系统补上最小必要说明**，
而不是把补齐的工作交回给刚发现自己"看不懂"的学生。

> **核心命题**：先回答学生问的问题；当他问不出来的时候，替他找出缺的那一块并补上。

**课程范围严格限定**：导数 / 切线 / 单调性。超出范围的推导一律标「未验证」，**不得假装通过**。

## 2 教学案例：一次真实的学习过程

### 2.1 场景

学生拿到一份只讲「单调性判定」的讲义，想弄明白"为什么 f′(x) > 0 就说明函数递增"。
但这份讲义**通篇没有解释导数是什么** —— 这是大学讲义里极常见的断裂。

### 2.2 两次提问，两种结果

| 步骤 | 学生做什么 | 系统做什么 |
|---|---|---|
| ① | **不上传任何材料**，直接提问 | 回答，但明确标注**未基于你的材料**，并提示上传讲义可获得更贴合的解答 |
| ② | 粘贴讲义 | 解析出知识点与前置关系，**落盘成图谱**；同时指出：判断单调性依赖**导数**，而这份讲义**没有解释导数**（`MISSING` / 材料未覆盖），并给出判定理由 |
| ③ | 点「补上这一段」 | 生成 200—400 字的最小必要说明，**显著标注「AI 补充：非上传讲义内容」**，验证状态标为**未验证** |
| ④ | 再问一次 | 这次回答标注**基于你的材料**，回答块带来源类别与验证状态，依据可展开查看 |
| ⑤ | 做练习 | 固定题与"按当前材料生成"的题分开；提交前不显示答案；自编题解析**不算作材料的证据** |
| ⑥ | 看画像 | 掌握状态与缺口历史有可见变化；并明说两条边界（见 §3.3） |

### 2.3 这个案例为什么值得做

学生真正的困难往往**不是他问的那个问题**，而是他自己不知道自己缺了什么 ——
缺的那一块没补上，问再多遍也只是把同一个障碍换一种说法。
本项目的教学价值集中在**"发现缺口并当场补齐"**这一步上，其余环节都围绕它服务。

### 2.4 演示时可用的固定案例

| 案例 | 期望结果 |
|---|---|
| x² 在 x = 1 处的导数 | 2 |
| 切线方程 | y = 2x − 1 |
| x³ − 3x 的单调区间 | 增 (1, +∞)、(−∞, −1)；减 (−1, 1) |

✅ **这三个案例已于 2026-09-20 成为符号验证引擎的固定基线断言**（`B3` 落地）：
实现与回归脚本**共用同一份期望值表**（`packages/teaching/src/symbolic.ts` 的 `FIXED_CASES`），
由 `npm run verify:symbolic` 自动核对；除正例外还配了**负例与越界例**
（只有正例的基线证明不了引擎有分辨力）。
因此现在可以如实说"**系统核对过**"，但仍**不得说"数学上被严格证明"**：
该引擎不是通用证明器，单调性用区间取样法，边界见 §4。

## 3 AI 用在哪里

### 3.1 四个调用点（全部经 `packages/teaching` 的提示词，全文见 `docs/tech/2026-09-17-B-提示词与工作流配置.md`）

| 调用点 | 做什么 | 关键约束 |
|---|---|---|
| 知识点与依赖抽取 | 从材料中抽知识点，并判定前置依赖 | 仅提及一个术语不算前置知识；必须给依据；依据不清标 `PENDING` |
| 缺口补充 | 生成 200—400 字最小必要说明 | 不得声称来自材料、不得编造引用、不得扩大课程范围 |
| 答疑 | 六类问题分类后作答（材料内 / 可推导 / 缺前置 / 部分支持 / 越界 / 条件不足） | 部分可答要分开说明；越界要引导回当前主题 |
| 按材料出题 | 依据当前材料生成练习题 | 每题唯一答案且必须能由材料解出；解析须指出所用规则 |

**模型只被允许通过注入的函数被调用**：教学模块不读密钥、不直接访问网络、不依赖托管平台，
因此可以离线单测（这也是回归能覆盖它、且不消耗额度的原因）。

### 3.2 AI 输出不被直接信任

所有模型输出都经过两道处理：

1. **归一**：`verification` 缺失或非法 → 一律落 **`unverified`**；
   状态缺失或非法 → 落 `partial` 而不原样透传；自依赖与循环依赖边一律丢弃。
2. **校验**：回答块若引用了不存在的来源、引用了未授权的补充块、或**摘录在来源里找不到**，
   该块被移入 `rejected[]` 并返回可重试错误 —— 这是"编造讲义引用"的拦截点。

### 3.3 三条明说的边界（写在界面上，不靠文档）

| 边界 | 为什么必须说 |
|---|---|
| 「我已掌握」**不会**把"材料未覆盖"改判为"已覆盖" | 学生的一句自我评价不能改变材料事实，否则覆盖状态就成了自我申报 |
| 「AI 已补充」**不等于**「已验证」 | 补充内容是模型生成的，未经验证不得暗示为可靠结论 |
| 补充内容**不跨会话迁移**，新会话回到 `MISSING` | 避免把上一轮临时补的内容当成学生长期掌握的部分 |

## 5 关于 AI 的使用方式（回应赛事手册相关要求）

- **AI 参与了开发**：本项目的开发过程本身使用了 LearnBuddy，四个阶段的对话记录与
  `docs/plans|changelogs|reviews|tech` 四类文档**互相溯源**。
- **AI 输出被核对、被否决、被修改的记录是真实的**：`docs/reviews/` 中每一轮都包含
  "AI 输出被否决或被修改"的实际条目（例：`reviews/2026-09-17-第7轮-todo复查与A侧界面收口评审.md`
  记录了 6 条，含一处 AI 结论有误被实测推翻、一处方案被结构性否决）。
  **这些记录不回填、不美化**，缺失即登记为缺失。
- **AI 不替代判断**：课程范围、状态机硬规则、真实性口径与交付承诺由团队确定；
  AI 负责在既定约束内实现与核对。

## 6 一句话总结边界

**能演示的**：材料进 → 缺口被发现 → 当场补齐 → **符号验证给出"已验证 / 未验证 / 验证未通过"** → 继续答疑 → 练习 → 画像变化，全程带来源与验证状态标注。
**不能演示的**：语音识别、教师视图、错题归因、**多智能体协作**；
**只能演一半的**：图谱关系边与符号验证的**真实通道**——mock 通道已跑通并如实标注，真实模型是否照新 schema 回答**未实测**。
**我们不把不能演示的写成能演示的**，也不在界面上留下"看起来能用"的空壳。
