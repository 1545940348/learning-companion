## 01 项目定位与范围

### 1.1 项目目标

围绕导数、切线与单调性，帮助学生读懂讲义中的文字、公式和图像。系统不仅整理知识点，还构建**多模态知识图谱**，指出当前学习需要哪些前置知识、材料是否覆盖、缺口如何补齐，并在答疑、练习、反馈中持续更新**学习者画像**。教师可通过教师视图查看班级整体掌握情况与常见误区。

**四条进入路径**：

| 路径 | 流程 | 适用场景 |
|---|---|---|
| **轻路径（默认）** | 拍照或粘贴 → 直接得到解释 → 可继续追问 → 按需转入材料路径 | 学生只有一道题、一句话、一张讲义照片 |
| **材料路径** | 上传材料 → 多模态解析 → 图谱构建 → 缺口自检与补充 → 分步答疑 → 练习 → 反馈 | 系统学习某主题 |
| **诊断路径** | 上传作业/练习 → 识别 → 错误归因 → 画像更新 → 推荐学习路径 | 学生想知道自己哪里不会 |
| **教师路径** | 教师查看班级画像、常见误区、材料覆盖热力图 | 教学管理 |

### 1.2 初赛优先级（修订）

## 02 学生学习流程与交互

### 2.1 零材料直接提问（轻路径）

- 输入：≤3000 字文字、≤5MB PNG/JPEG、≤60 秒语音，或任意组合；
- 系统直接给出解释，标注"未基于你的材料"；回答遵循第 04 章边界规则；
- 提供一次性"上传讲义可获得更贴合解答"提示，不阻断；
- 学生可随时转入材料路径；转入后系统抽取知识点与依赖，并提示历史回答是否需要重新核对；
- 轻路径不生成知识点卡片，但**生成轻量画像事件**（问题主题、是否含公式、是否含图像）。

### 2.2 多模态输入与识别

识别结果默认直接用于后续教学。

- 识别文本以可编辑形式展示；模糊或不完整公式标注"识别可能不准"；
- 学生可就地修改；修改后系统重建受影响的知识点、图谱节点与前置依赖，已生成回答标记"依据已更新"；
- 无刻度示意图不据此估算精确数值；
- 每个学习会话最多 **5 份**材料，文本与图像描述合计不超过 **15000 字**；超限提示缩短或开始新学习；
- 图片解析为文本/描述后参与教学，不反复发送所有图片；
- **公式识别**输出 LaTeX 并保留符号语义，供符号验证使用；
- **图像理解**输出结构化描述（图表类型、坐标轴、关键点、趋势），供图谱资源层使用；
- **语音输入**经 ASR 转写后进入文本管线，保留时间戳以便溯源。

### 2.3 知识点与前置提示（图谱驱动）

展示当前会话 3—6 张核心知识点卡片，包含名称、解释、公式与条件、来源、误区、图谱邻域。

卡片下显示：

> 这部分需要导数知识，当前材料没有解释。
> 　[ 补上这一段 ]　[ 我已掌握，继续 ]　[ 查看图谱 ]

点击"补上这一段"后，系统生成当前主题所需的**最小必要说明**（200—400 字），显著标注为 AI 补充内容，并入当前会话材料，图谱依赖状态更新，并触发符号验证。

学生也可选择"我已掌握，继续"，直接进入答疑；该选择只影响引导，不改变材料覆盖状态，但会写入画像事件。

**图谱视图**（P1）：以当前知识点为中心，展示前置、后继、并列、例证关系；缺口节点高亮；点击节点可展开来源与资源。

### 2.4 两种上传动作

| 操作 | 行为 |
|---|---|
| **补充当前材料** | 加入新素材，保留旧材料与图谱；重建成功后更新依赖；失败保留旧状态；更新后清空当前练习选择与反馈，旧聊天仅作历史展示 |
| **开始新学习** | 经确认后生成新会话，清空材料、图谱、聊天、练习状态；AI 补充内容不迁移；画像事件跨会话保留（P1） |

### 2.5 答疑

保留"解释概念""给我提示""查看完整解答"三种模式。默认先给提示，完整解答由学生主动选择。

- 回答默认以**简洁正文 + 引用角标**呈现；点击角标展开"依据详情"；
- 依据详情包含：来源类别、引用片段、所用规则、**验证状态**（已符号验证/已人工核验/未验证）；
- AI 补充内容不适用降权规则，始终显著标注；
- 数学推导由**符号验证 Agent**独立校验；校验失败时触发修正回环，而非直接输出；
- 多智能体协作：答疑 Agent、验证 Agent、诊断 Agent、出题 Agent 由编排层协调；
- 回答可包含动态生成的可视化（matplotlib/TikZ/p5.js），标注为"AI 生成图示"。

### 2.6 练习与反馈

| 类型 | 数量 | 来源标注 |
|---|---|---|
| **固定题** | 每主题 3 道单选题 | "项目自编练习" |
| **按材料出题** | 基于当前会话材料生成 2 道，可重复生成 | "基于你的材料生成" |
| **变式题（P1）** | 根据画像弱点生成 1—2 道 | "根据你的学习情况生成" |

提交前不展示答案；答错后解释误区并引导复习；答对后建议继续。解析注明所用规则与验证状态。若依赖材料未覆盖，先提示并允许补充。自编练习解析不计为材料证据。

**错题归因（P1）**：区分概念误解、计算错误、条件遗漏、识别错误，写入画像。

## 03 多模态知识图谱与动态更新

### 3.1 图谱结构

采用三层图谱：

- **概念层**：知识点节点（ID、名称、定义、公式、条件、误区）
- **资源层**：每个概念关联的多模态资源（讲义片段、示意图、例题、讲解、AI 补充块）
- **认知层**：学习者掌握状态、常见错误模式、认知负荷标记

关系类型：

| 关系 | 含义 |
|---|---|
| `prerequisite` | 学习当前知识点前需要了解 |
| `derives` | 可由前置推导 |
| `illustrates` | 例证 |
| `contrasts` | 对比/易混 |
| `extends` | 推广/特例 |
| `depends_on` | 计算或证明依赖 |

初赛以 `prerequisite` 为核心，其余关系用于答疑与出题。

### 3.2 依赖状态（扩展）

| 状态 | 判定与行为 |
|---|---|
| **LOCAL：材料已覆盖** | 当前任一材料中有足以支持当前学习目的的定义、规则或说明，并能定位来源 |
| **SUPPLEMENTED：已由 AI 补充** | 材料原本缺失，经学生点击后由系统补齐，内容显著标注，可定位到补充块 |
| **MISSING：材料未覆盖** | 当前学习明确需要该概念，所有材料均无解释，学生尚未补充 |
| **待确认** | 依据不清晰或公式识别不完整，列为待确认 |
| **VERIFIED：已验证** | 补充或推导内容通过符号验证或人工核验 |
| **DISPUTED：有争议** | 验证失败或来源冲突，需人工介入 |

### 3.3 图谱构建管线

1. **抽取**：LLM 从语义分块中识别概念、关系、属性；
2. **归一**：同义概念合并，排除自依赖与循环依赖；
3. **验证**：符号验证 Agent 校验公式与推导；人工核验关键结论；
4. **增强**：GraphRAG 多跳推理补全隐含关系，标注为"推断"；
5. **提交**：整体提交新版本，保留稳定 ID。

### 3.4 更新规则

- 每条前置关系包含依赖概念、状态、理由、依据、验证状态；
- 补充材料或补充缺口后重新检查当前关系，保留稳定编号；
- MISSING → LOCAL 仅当新增材料确实提供说明；
- MISSING → SUPPLEMENTED 仅当学生实际点击并生成成功；
- SUPPLEMENTED → VERIFIED 仅当符号验证或人工核验通过；
- SUPPLEMENTED 不因学生表示"已会"而转为 LOCAL；
- 会话之间不共享 AI 补充内容；新会话中同一概念回到 MISSING，可再次按需补充。

### 3.5 核心演示案例

初始素材讲解"依据 f′(x) 的符号判断 f(x) 单调性"，未说明导数定义。系统：

1. 保留单调性知识点；
2. 图谱标记导数前置为 MISSING；
3. 同屏提供"补上这一段"与"查看图谱"；
4. 学生点击后生成导数定义最小必要说明，标注 AI 补充；
5. 符号验证 Agent 校验导数定义与示例；
6. 状态转 SUPPLEMENTED → VERIFIED；
7. 结合原始素材与补充内容解释，进入练习；
8. 画像记录"导数概念缺口已补"。

对照路径：学生补充导数定义讲义，状态转 LOCAL，用于展示材料来源与 AI 补充的来源区分。

### 3.6 工程与边界

- 图谱存储采用轻量图结构（内存图 + JSON 持久化），初赛不引入 Neo4j；
- 关系判断由教学模块生成结构化结果，程序校验编号、来源、关系结构；
- 数学合理性由符号验证 + 固定案例验证；
- 不扩展到高数全课程网络；
- 图谱可视化（P1）只读，不提供图形编辑器。

## 04 回答边界、来源与验证

### 4.1 哪些问题可以回答

| 情况 | 处理方式 |
|---|---|
| 材料明确包含 | 基于对应材料回答并引用 |
| 可依据材料推导 | 允许新例题与计算；标记基于材料的解释/推导，列出条件与规则 |
| 缺少前置知识 | 说明缺少什么，同屏提供补充入口 |
| 部分支持 | 分别指出材料不足或超出范围的部分 |
| 超出课程范围 | 说明仅支持导数、切线与单调性，引导回到当前主题 |
| 题目条件不足 | 指出缺少条件，先澄清，不混同于缺少知识素材 |
| 零材料提问 | 可用通用知识回答，标注"未基于你的材料"，遵守课程范围 |

### 4.2 按需补充与授权

- 取消全局"外部参考开关"，改为**按动作授权**；
- 未点击时，系统不主动生成任何 AI 补充内容；
- 点击后生成最小必要说明，显著标注"AI 补充：非上传讲义内容"，并入当前会话材料；
- 不默认联网，不编造外部文献链接；
- 补充内容受课程范围约束；
- 生成中切换会话或开始新学习，丢弃未完成补充；
- 补充内容仅在其所属会话内有效；
- **补充内容必须经过符号验证或标记为"未验证"**，不得默认视为正确。

### 4.3 三类教学来源与校验

1. **来自讲义**：引用编号有效，摘录可在对应材料中找到；
2. **根据讲义解释/推导**：绑定支持规则或片段，与直接引用分开；
3. **AI 补充/外部内容**：仅在学生按需授权后生成，不使用伪造讲义引用。

**数据与校验层完整保留三类来源**：每个教学内容块返回来源类型、引用、验证状态。B 校验结构、编号及摘录匹配；C 统一映射模型错误；符号验证 Agent 校验数学结论。

**界面层降权**：默认只呈现正文与引用角标，来源分类收进"依据详情"。例外：AI 补充内容必须显著标注；验证失败内容必须显著提示。

### 4.4 符号验证（新增）

- 对导数、切线、单调性相关推导，调用 SymPy 或等价符号引擎；
- 验证内容：求导结果、切线方程、单调区间、极值点；
- 验证通过：标记"已符号验证"；
- 验证失败：标记"验证未通过"，触发修正回环或人工介入；
- 验证超时：标记"未验证"，不阻断答疑但如实展示；
- 验证记录写入开发文档与图谱节点。

### 4.5 多智能体协作（P1）

| Agent | 职责 |
|---|---|
| 答疑 Agent | 生成解释、提示、完整解答 |
| 验证 Agent | 符号验证、来源校验、冲突检测 |
| 诊断 Agent | 更新画像、识别盲区、推荐路径 |
| 出题 Agent | 生成变式题、按材料出题 |

编排层负责路由、重试、冲突消解。任一 Agent 失败不影响主流程，降级为单 Agent 模式并如实标注。

## 05 技术架构与共享接口

### 5.1 分层架构

- **前端**：React + TypeScript，负责交互、图谱视图、画像视图、教师视图
- **教学模块**：独立 TypeScript 模块，负责提示词、依赖分析、补充生成、输出校验、符号验证接口
- **服务端**：Node.js + TypeScript，负责模型适配、会话、图谱存储、部署
- **数据层**：轻量图存储 + 向量索引（可选）+ 会话存储

单仓库、一个 Web 服务；**不强制不用向量数据库**，但初赛以轻量索引为主。

### 5.2 模型通道

- 默认 DeepSeek API，统一由 `ModelCaller` 抽象；
- 视觉、嵌入、语音为可替换通道；
- 密钥仅服务端保存；
- 学生界面不常驻模型品牌；
- 技术文档、启动日志、`GET /api/health` 如实报告通道；
- 真实联调显式使用 `deepseek`；验收要求 `modelProvider=deepseek` 且 `mock=false`；
- 缺少密钥或模型失败时明确报错，不静默切换；
- 结构化输出需运行时字段与来源校验；
- 单次业务请求 90 秒总预算（含验证），重试计入同一预算。

### 5.3 共享契约

| 接口 | 输入 → 输出 |
|---|---|
| `POST /api/session` | 创建会话 → 会话 ID、`materialVersion=0`、空图谱状态 |
| `GET /api/health` | → 服务版本、`modelProvider`、`mock`、验证引擎状态 |
| `POST /api/parse` | 文字、图片、语音 → 识别文本、公式 LaTeX、图像描述、低置信度标记 |
| `POST /api/knowledge` | 会话、材料、补充块 → 图谱节点、关系、来源、验证状态 |
| `POST /api/tutor` | 会话/版本、问题、知识点、模式、历史 → 边界判断、分块回答、来源、验证状态、下一步 |
| `POST /api/gap` | 会话、版本、缺口 ID、理由 → 补充内容、来源标记、补充块 ID、更新后状态 |
| `POST /api/quiz` | 主题、来源类型、会话 → 题目、选项、答案、解析、依据、验证状态 |
| `POST /api/profile` | 会话、事件 → 更新后的画像 |
| `GET /api/graph` | 会话、知识点 → 图谱邻域 |
| `GET /api/teacher` | 班级 ID（P1）→ 聚合画像、常见误区、材料覆盖热力图 |

**共享类型至少包含**：会话 ID、材料版本；素材 ID 与文本；补充块 ID 与授权标记；知识点 ID 及来源；关系类型与状态；回答块来源类别与引用；验证状态；画像事件类型。

### 5.4 会话与错误处理

- 每份材料独立 ID，更新递增版本；
- 新学习使用新会话 ID；
- 响应仅在会话与版本匹配时应用；
- 换课、补充、新学习时丢弃旧请求；
- 补充失败不清空已有状态；
- 当前标签页保存材料文本、图谱、进度；刷新可恢复；
- 图片不长期保存；文本可追溯；
- 模型请求超时返回可重试错误并保留输入；
- 验证失败不阻断主流程，但如实标注。

### 7.1 自编素材与固定题

- **导数**：x² 在 1 处的差商与导数，结果为 2；
- **切线**：x² 在 1 处切点 (1,1)，切线 y = 2x − 1；
- **单调性**：x³ − 3x 在 (−∞,−1)、(1,+∞) 递增，在 (−1,1) 递减。

每主题文字、图片、语音版本，共 9 份；单调性素材保留导数前置缺口，支持"一键补充"与"补充讲义"两种路径。

## 10 验收与边界测试

### 10.1 教学与主流程

6—9 份图文语音素材逐项核验公式；每会话显示 3—6 个核心知识点；12 个答疑问题覆盖概念、计算、误区、条件不足；9 道固定题答案唯一；按材料出题附依据；三个主题分别在新会话完成答疑与练习；单调性缺口演示两条补齐路径；符号验证覆盖核心数学结论。

| 编号 | 边界用例 | 期望结果 |
|---|---|---|
| E1 | 单调性材料仅提导数，没有解释 | 标 MISSING，提供补充入口；不自动生成 AI 内容 |
| E2 | 原文解释导数，但未显示导数卡片 | 判 LOCAL；不因卡片缺席误判 |
| E3 | 补充导数素材/补充无关素材 | 前者转 LOCAL；后者保持 MISSING |
| E4 | 新例题可依材料计算 | 允许推导并标注依据 |
| E5 | 完全越界/部分可答 | 越界引导返回；部分分开回答 |
| E6 | 未点击/点击补充 | 未点击不生成；点击后生成、标注、转 SUPPLEMENTED |
| E7 | 模型返回假引用或未授权内容 | 校验失败，不作为正常答案 |
| E8 | 换课时旧回答迟到 | 新会话不出现旧内容 |
| E9 | 补充失败、刷新、达到上限 | 失败保留旧状态；刷新恢复文本；超限提示 |
| E10 | 会话 A 的 AI 补充与会话 B | 不进入 B；B 中该概念回到 MISSING |
| E11 | 零材料提问 | 可完成有效答疑并标注 |
| E12 | 识别有误，用户就地修改 | 图谱重建；已生成回答标记"依据已更新" |
| E13 | 补充生成中切换会话 | 丢弃未完成补充 |
| E14 | 符号验证失败 | 标记"验证未通过"，触发回环或人工介入 |
| E15 | 图谱循环依赖 | 归一阶段排除，不进入图谱 |
| E16 | 画像事件跨会话 | 补充内容不迁移，画像事件按规则保留 |
| E17 | 教师视图数据脱敏 | 不展示个人身份信息 |
| E18 | 多智能体降级 | 验证 Agent 失败时主流程继续，标注降级 |

### 10.2 执行责任与发布条件

B 主测 E1—E7、E12、E14、E15 与数学内容；C 主测 E8、E10、E11、E13、E16、E18 及接口异常；A 复核全部界面表现。另测空输入、超限图片、模糊公式、无效密钥、超时、格式错误。

**核心边界必须实际通过。** 已知数学错误、错误来源、未授权 AI 内容、会话串扰、验证失败未标注均须修复后发布。
