## 01 初赛作品形态的澄清

### 1.1 「demo 即可，不用部署到正式环境」的含义

**【原文】** 不用部署到正式环境。

**【澄清】明确不包含以下要求：**

- 生产级部署与容量规划；
- 高可用、多副本、容灾与自动扩缩容；
- 正式域名与备案；
- 长期运维、SLA 或线上售后；
- 正式环境的账号体系、权限体系、计费体系。

**【澄清】仍然包含以下要求（不因"demo 即可"而豁免）：**

- 作品本身**真实可跑**，不是录屏、截图或静态页面；
- 评委可**在一个浏览器会话内完成一次真实交互**；
- 核心链路真实执行。若使用 mock，必须**当场可见地标注为 mock**。

> 一句话：**放宽的是"运行环境的等级"，不是"作品的真假"。**

### 1.2 「浏览器环境、在线链接」的含义

**【原文】** 须部署至浏览器环境，提供可直接访问的在线链接。

**【澄清】**

- 评委**用浏览器打开链接即可访问并交互**，无需安装、无需本地启动、无需阅读部署文档；
- **不得**只提交本地截图、录屏，或"请按 README 在本地跑起来"的说明 —— 这些不能替代在线链接;
- 链接必须**真实可访问**（可在无痕窗口打开即视为通过自检）。

**【建议】** 目标为桌面浏览器可用；不要求移动端适配（主办方未提，我方不额外增加工作量）。

### 1.3 两种作品形态均可

**【原文】** 可以是 web demo，也可以是专家智能体。

**【建议】以 Web demo 为主、LearnBuddy 专家智能体为辅。**

理由：Web demo 可自由承载自定义界面（知识图谱视图、学习画像视图、教师视图、依据详情展开），
这些正是 V2.0 技术深化模块的展示位置；专家智能体的优势是与 LearnBuddy 平台原生集成、
更贴近平台形态。二者互补，不是二选一 —— 若时间允许，**两个入口同时提供**。

### 1.4 「可交互体验」是硬要求

**【原文】** "这些智能体做完之后是可以跟它进行交互体验使用的"。

**【澄清】** 可交互是硬要求，因此：

- 只读页面、静态介绍页、PPT 式展示**不满足**；
- 演示路径至少覆盖第 08 章列出的**核心闭环**；
- mock 演示入口也必须是**可交互**的，不能只放一段说明文字。

## 04 部署与密钥调整

### 4.1 部署目标

**【原文】** 不用部署到正式环境。

**【澄清】** 意味着：不要求生产级稳定性、不要求正式域名、不要求长期运维。
**但要求**：核心链路在 demo 环境中**真实可跑**，且评委能访问。

### 4.2 可用部署载体（【建议】）

| 载体 | 适用 | 备注 |
|---|---|---|
| Vercel / Netlify | 前端静态产物 + Serverless 函数 | 需处理前端与接口的同源或跨域 |
| 腾讯云静态托管 | 前端静态产物 + 云函数 | 与赛事主办方生态一致 |
| 临时隧道 | 本地服务临时对外 | 仅作应急，**链接存活期必须覆盖评审期** |
| LearnBuddy 体验链接 | 专家智能体形态 | 与平台原生集成 |

**必须**：无论选哪种，**链接在评审期内必须保持可访问**。临时隧道需明确其有效窗口。

### 4.3 密钥（本项为硬要求）

**【原文】** 在线链接须可直接访问 → 引申为：**评委体验时不得要求配置 DeepSeek 密钥。**

**必须做到以下之一：**

1. 提供**已配置好服务端密钥的演示环境**（密钥只存服务端，永不进前端与仓库）；或
2. 提供**可用的 mock 演示入口**，使评委无需任何密钥即可走完核心闭环。

**必须**：真实调用与 mock 演示**明确区分**，mock 标记**照常保留**，不得隐藏或弱化。
（现有实现中 `/api/health` 会如实报告 `modelProvider` 与 `mock` 字段，界面顶部有对应提示。）

### 4.4 真实性与标注

- 在线链接必须真实可访问，**不能是"本地跑起来"的说明**；
- 技术深化模块**可以部署在 demo 环境中**，不要求生产级稳定性；
- **但核心链路必须真实可跑** —— 不接受的替代形式：预录视频、写死的假数据流、只在文档里描述的技术能力。

### 4.5 已知前提（团队内部，非主办方要求）

**【团队约定】** 部署前必须先解决一个已验证的阻断项：

> 当前 `npm run build` 成功，但**构建产物无法用原生 node 启动**
> （报错：找不到 `packages/contracts/src/session.js`）。
> 根因是共享包的类型入口指向 TypeScript 源码，原生 node 无法解析其内部 `./x.js` 引用。
> **影响：在线链接无法交付。** 本地演示目前依赖开发期运行器，不能作为提交形态。

修法二选一：① 构建时把共享包一并打包进产物；② 为共享包补真正的构建步骤并让入口指向产物。
**必须在制作在线链接之前完成**，否则第 02 章第 1 件提交物无法交付。

- 确保技术深化模块**可演示、可验证**（有可复现的输入与期望输出）。

**尽量完成**
- 多智能体协作与降级机制；变式题；错题归因。

### 7.3 成员 C：服务、集成与部署

**必须**
- **优先搞定可访问的在线链接**，不追求正式环境；
- 维护 LearnBuddy 对话记录与四类开发文档；

**尽量完成**

### 7.4 三人共同

## 08 验收标准调整

### 8.1 初赛验收口径

**【澄清】以"评委能点开、能交互、核心闭环可演示"为初赛验收口径。**

| 层级 | 判定 |
|---|---|
| 不合格 | 链接打不开、只有静态页、评委需配置密钥才能用 |
| 合格 | 链接可访问，能在浏览器中完成一次真实交互，核心闭环可演示 |
| 优秀 | 合格 + 技术深化模块在演示中真实可见（图谱、验证、画像、教师视图等） |

### 8.2 核心闭环（演示必须走通）

> 零材料提问 → 上传讲义 → 图谱构建 → 缺口发现 → 一键补充 →
> 符号验证 → 继续答疑 → 练习 → 画像更新

**必须**：该闭环在一次演示中完整走通。任一环节不可演示，即为阻断项。

### 8.3 技术深化亮点（加分项，尽可能呈现）

- 图谱可视化：以知识点为中心的邻域展示，缺口节点高亮；
- 符号验证状态：已验证 / 未验证 / 验证未通过 在依据详情中可见；
- 多智能体降级机制：某 Agent 失败时主流程继续并如实标注；
- 画像变化：会话内掌握状态与缺口历史的可见变化；
- 教师视图：班级聚合、常见误区、材料覆盖热力图（只读、脱敏）。

### 8.4 真实性底线

- **不要求所有 P2 模块上线**；
- **但已宣传的技术能力必须真实可演示，不能以 mock 冒充真实能力**；
- 未实现项须在作品与材料中**明确标注为未实现或后续迭代**。

### 8.5 进度纪律

- **初赛不因技术深化而拖延提交**；
- 时间宽裕时**优先保障技术深度**；
- 若某项确实无法完成，正确做法是**如实降级标注**，而不是删掉文档中的表述
  或让它以"看起来能用"的形式存在。
