### 4.2 依赖六态（§3.2）

```
MISSING ──学生点击补充──▶ SUPPLEMENTED ──符号验证/人工核验通过──▶ VERIFIED
   │                            │
   │新增材料确有说明             └──验证失败或来源冲突──▶ DISPUTED
   ▼
 LOCAL
PENDING（待确认）为旁置态：依据不清晰或公式识别不完整
```

**硬规则**（§3.4）：`SUPPLEMENTED` **不因学生表示「已会」转为 `LOCAL`**；补充内容不跨会话迁移，新会话中同一概念回到 `MISSING`。

### 4.3 验证状态（§2.5 / §4.4）

建议类型（待 C 在契约中确认命名）：

```ts
type VerificationStatus =
  | 'symbolic'    // 已符号验证
  | 'human'       // 已人工核验
  | 'unverified'  // 未验证（含超时，如实展示不阻断）
  | 'failed';     // 验证未通过，触发修正回环或人工介入
```

**自编素材与固定题**（§7.1，不可改动数值）：

- **导数**：x² 在 1 处的差商与导数，结果 2；
- **切线**：x² 在 1 处切点 (1,1)，切线 y = 2x − 1；
- **单调性**：x³ − 3x 在 (−∞,−1)、(1,+∞) 递增，在 (−1,1) 递减。

每主题文字/图片/语音三版，共 9 份；单调性素材**保留导数前置缺口**，支持「一键补充」与「补充讲义」双路径。

## 6 P1 全量设计（D2：本轮收入计划，实现按阶段三排入）

### 6.1 教师视图（`GET /api/teacher`）

**目标**：教师查看班级整体掌握情况与常见误区，作为次级用户入口。

| 项 | 设计 |
|---|---|
| 数据模型 | `ClassAggregate = { classId, studentCount, mastery: Record<conceptId, {local, supplemented, missing, verified}>, misconceptions: {conceptId, pattern, count}[], coverageHeat: {materialId, conceptId, covered: boolean}[] }` |
| 数据来源 | 由**画像事件**按班级聚合；不读取个人问答原文 |
| 接口 | `GET /api/teacher?classId=` → 上述聚合体 |
| 脱敏 | 只输出计数与概念维度统计，**不含学生 ID、姓名、原始提问**（E17） |
| 界面 | 三块：掌握度条形、常见误区列表、材料覆盖热力图（只读，无编辑） |
| 边界 | 班级数据量不足时明确提示「样本不足」，不生成误导性结论 |

### 6.2 语音输入（§2.2）

| 项 | 设计 |
|---|---|
| 通道 | ASR 经 `ModelCaller` 抽象为可替换通道，密钥仅服务端 |
| 约束 | ≤60 秒；转写后进入**文本管线**，不留专用旁路 |
| 溯源 | 保留时间戳；低置信度片段与文字识别共用同一标注机制 |
| 失败 | ASR 不可达时明确报错并保留原音频提示，**不静默降级为文字猜测** |
| 验收 | 三个主题各 1 份语音素材可走通完整材料路径 |

### 6.3 多智能体编排（§4.5）

| Agent | 职责 | 失败降级 |
|---|---|---|
| 答疑 Agent | 生成解释 / 提示 / 完整解答 | 主流程 |
| 验证 Agent | 符号验证、来源校验、冲突检测 | 失败 → 标「未验证」，主流程继续 |
| 诊断 Agent | 更新画像、识别盲区、推荐路径 | 失败 → 跳过画像更新，不阻断 |
| 出题 Agent | 变式题、按材料出题 | 失败 → 回落到固定题 |

**编排层**职责：路由、重试、冲突消解。**任一 Agent 失败均降级为单 Agent 模式并如实标注**（E18），不得静默。实现上复用现有 `createTeachingModule` 闭包结构，按 Agent 拆分任务函数，不引入外部编排框架。

### 6.4 图谱可视化（§2.3）
