# 本轮计划：PR #2 收口与错误层自洽

- **日期**：2026-09-17
- **授权**：负责人本轮指令「全量推进，然后合并」—— 授权把独立评审（`docs/reviews/2026-09-17-PR2独立代码评审.md`）列出的问题全部修完，并合并 PR #2。
- **起点**：分支 `feat/c-deepseek-backup` @ `82866a6`（PR #2 的 head）。

## 背景

PR #2 的三件主功能（DS 默认通道、`/knowledge` 原子提交、模型错误映射与 60 秒预算）经独立复现已成立，但评审发现错误层自身不自洽：同一个契约错误码在两条路径上给出不同的状态码与 `retryable`，而前端 `apps/web/src/api.ts` 只凭 `retryable` 决定要不要给"一键重试"。本轮把这些问题收干净，目标是「错误层可信、入参不再把内部报错回给客户端」。

## 任务分解

| # | 任务 | 落点 | 验收条件 |
|---|---|---|---|
| 1 | `retryable` 由错误码推导，不在分支里写死 | 新增 `src/http/error-response.ts` | `SESSION_STALE` 在入口与提交复核两条路径上**同为 409 + retryable:true**；`INTERNAL` 为 retryable:false |
| 2 | 畸形 JSON 请求体归 400，不再 500，且不回显解析器原文 | 同上 + `errorHandler` | `body = '{bad json'` → **400 `BAD_REQUEST`**；超过体积上限 → 413 |
| 3 | 轻路径 `sessionId` 省略不得判为越权 | `src/http/routes.ts` | `{question}` 与 `{question, sessionId:null}` 行为一致（均 200） |
| 4 | 入参形状校验，拒绝非法结构 | 新增 `src/http/request-guards.ts` | `materials:"abc"`、`[{id}]` → **400**，不再 500 且不泄露内部报错 |
| 5 | `deepseek.ts` 保留 `error.cause` | `src/model/deepseek.ts` | 网络类失败时 `detail` 含 DNS/证书等真实原因，不再是裸 `TypeError: fetch failed` |
| 6 | 记录上游回显的 `model` 与 `usage` | `src/model/deepseek.ts` | `model.call.meta` 日志含 `requestedModel` / `actualModel` / `usage`，落实说明书 V1.4 §5.2 |
| 7 | 文案与配置解耦 | `src/model/budget.ts`、`errorHandler` | `MODEL_TIMEOUT_MS=1` 时提示"1 秒"，不再硬编码 60 秒 |
| 8 | 统一 404、校验 `topic`、配额文案含本次份数、修正过期注释 | `routes.ts`、`store/index.ts`、`model/index.ts` | 未知 `/api/*` 返回 JSON；`topic=nope` → 400；配额提示含本次份数 |
| 9 | 统一 README 耗时数据与 changelog 一致 | `README.md` | 与 `docs/changelogs/2026-09-17-C-DS转为默认通道.md` 的 1213 ms／3195 ms 对齐 |
| 10 | 补齐留痕：本轮 plan／changelog／review，并给历史 tech 记录加版本指向 | `docs/` | 四类文档齐全；review 含本轮真实被否决／被修正的判断 |

## 不做的事（明确排除）

- **不改契约**：`packages/contracts` 与 `packages/teaching` 保持零改动，A 与 B 不受影响。
- **不新增 `ApiErrorCode` 取值**：细分类别继续由 HTTP 状态码承载（沿用 PR #2 已确认的取舍）。
- **不发真实模型调用**：本轮验证全部为本地纯函数与环回假上游，不消耗额度、不需要密钥。
- **不动 SDK 历史通道**：`MODEL_PROVIDER=sdk` 的代码保留，仍不参与自动降级。
