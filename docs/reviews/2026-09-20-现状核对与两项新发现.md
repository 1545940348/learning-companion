## 四、两项新发现（`packages/teaching`，代码层；属 B 的目录 → **本轮只登记不改**）

### 4.1 N1 —— `[null, null]`（全实轴）被**规范化层**拒绝，且拒绝理由与输入矛盾

**事实链**（`packages/teaching/src/symbolic.ts`）：

- `:81` 注释自述：「位置 0 的 `null` 是 −∞，位置 1 的 `null` 是 +∞」→ 按此，`[null, null]` 就是 (−∞, +∞)；
- `:232` 实际判据：`const lowIsNegInf = rawLow === null && rawHigh !== null;` → `[null,null]` 时 `lowIsNegInf = false`，`toBound(null)` 返回 `pos-inf`；
- `:239` `if (low.kind === 'pos-inf' || high.kind === 'neg-inf') return null;` → **整条断言被丢弃**，`method` 落到 `-`（**根本没进引擎**）；
- 给学生的理由是「端点须是有限数或 null」——**输入恰恰就是 `null`**，理由与输入矛盾；
- 连带：`samplePoints:431`（`if (low === null && high === null) return null;`）**专门为"两端都无界"写的那条分支，对 `null` 写法成了死代码**，它那句干净的说明永远走不到。

**实测对照**（同一语义、两种写法）：

| 写法 | 结果 | 理由 |
|---|---|---|
| `inc: [[null, null]]`（**提示词教模型写的**，`prompt.ts:69`） | `unverified`，`method = -` | 「`claimed.inc` 不是合法区间数组（…端点须是有限数或 null）」←**误导** |
| `inc: [['-∞', '∞']]`（未文档化的字符串写法） | `unverified`，`method = interval-sampling+endpoint-zero` | 「区间 (−∞, +∞) 两端都无界，取样法覆盖不了整条实轴（如实标未验证，不假装通过）」←**干净** |

**影响**：对"整个定义域上单调"的函数（`f = x³ + x` 这类），模型最自然的写法拿到的是一条**自我矛盾的"未验证"**，而正确写法（字符串）只在代码里存在、提示词没教。

### 4.2 N2 —— 分界点校验会把**正确**断言判 `failed`（→ 学生看到"有争议"）

**事实链**：`symbolic.ts:498-509` —— 任何被 **≥2 个区间共享**的有限端点都要求 `f′(b) = 0`。

**实测**：

| 断言（f = `x^3+x`，全轴递增、**无驻点**） | 结果 |
|---|---|
| `inc: [[null, 0], [0, null]]`（按 x=0 拆成两段） | **`failed`**：「区间分界点 x = 0 处 f′(x) = 1 ≠ 0，与"这里是增减分界"矛盾」→ 落到 `/api/gap` 即 **`DISPUTED`（有争议）** |
| `inc: [[null, null]]` | `unverified`（见 N1） |
| 对照：同拆法用于 `f = x^3`（x=0 **恰是**驻点） | `verified` |

**结论**：全定义域单调的函数**两种写法都到不了 `verified`**，其中一种还会把**正确内容**标成"有争议"。判据实际上把"**极大**单调区间"当成了隐含前提，而提示词从未这么要求。经本轮穷举探针（`FIXED_CASES` 10 例 + 上述 4 组），这是该引擎目前**唯一**能把正确内容判成 `failed` 的路径（F5/F6/F7 三个负例都对应真实错误）。

**建议处置**（最小改动、不重构 —— `symbolic.ts` 已 852 行）：N1 改 `:232` 判据（`null` 在位置 0 一律视为 −∞）+ 修理由文案；N2 把共享端点改为"是驻点则校验、不是则跳过并在 notes 里说明"，不要直接 `failed`。两条各补一条断言进 `verify:symbolic`。

## 五、被否决 / 被订正的记录（评审必含）

### R1 —— **否决**：B 在 `PR #13` 评论里提的那处补丁，实测**不成立**

**B 的原话**（`PR #13` 关闭评论）：
> 若模型仍以数字大数（如 `1e6`）表达开区间端点，#12 会把它当有限端点，在 x=1e6 处做「分界点 f′=0」校验 → 算得 f′≠0 → **把正确断言误判为「验证未通过」**。

**核实结果：不成立。** `symbolic.ts:498-499` 的先决条件是"该端点**被 ≥2 个区间共享**"（`if (count < 2) continue;`）——单侧出现的大数端点只计 1 次，**不触发任何分界点校验**。实测（`probe-monotonic.ts`）：

| 断言 | 结果 |
|---|---|
| `(a)` 规范写法 `inc:[[null,-1],[1,null]] / dec:[[-1,1]]` | `verified` |
| `(b)` **B 描述的场景** `inc:[[-1e6,-1],[1,1e6]] / dec:[[-1,1]]` | **`verified`**（理由明写"共 4 个候选分界点里**被共享的那些**…"） |

**处置：该补丁不进 `#12`。** 理由不只是"没复现"：把大数端点当无界是**静默容忍一个真实错误**（模型声称 (−∞,−1]∪[1,+∞)、实际给的是有界区间，本应如实暴露）—— 收这份补丁会把"严格"换成"宽容"，代价与收益不对称。
**但方向被采纳**：B 担心的"把正确断言判成 `failed`"**确实存在**，机制在 **N2**（共享端点是非驻点的拆段），不在大数端点。→ 按「**方向对、机制错、补丁不进**」登记；`feat/teaching-symbolic` 分支**无需摘取**。
