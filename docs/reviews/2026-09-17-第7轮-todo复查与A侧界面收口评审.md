## 2 被否决 / 被修改的 AI 输出（逐条留痕）

### 2.1 ✗ **我上一轮的一个结论是错的，已更正**

- **我说过**：「`docs/todo.md` 统计块写『共同 J 12 条』，表内实为 13 条」。
- **实际**：用 `grep -n "编号化条目\|共同 J" docs/todo.md` 复核 —— **`todo.md` 里没有这个统计块**。
  那个统计块在 `.learnbuddy/memory/2026-09-17.md`（轮次工作日志）第 369–370 行，是上一轮我记日志时写的。
- **根因**：把「我记的日志」与「待办总表」混为一谈 —— 两者都在昨天同一轮里产生，我按印象归了位。
- **处置**：① 本轮**没有**在 `todo.md` 里"修正"这个不存在的漂移；② 在 changelog §1.1 与本文件登记更正；
  ③ 本轮改 `todo.md` 时，凡是引用数字的地方都先 `grep` 定位再改。
- **教训**：**引用文件内容前必须先取到该文件的原文**。同一天产生的多份文档尤其容易张冠李戴。

### 2.2 ✗ **我先写了一个没量过的数字，被自己的实测打回**

- **我做过**：在整理 README 时写下「回归脚本 **272 项全部通过**」（190+32+8+**42**），
  其中 42 是**上一轮记录的** `verify:render` 项数；我引用时它已经不对了 —— 本轮为 `P-A8` 补了 16 项断言后是 **58**。
- **实际**：跑完四套后是 **190 + 32 + 8 + 58 = 288**。
- **处置**：把 `README.md`、`docs/todo.md`（`P-C5`、`P-A15`）、`docs/知识库.md` §9 **四处**统一改为 58 / 288。
- **教训**：**写数字必须在本轮实测之后再写**，不能"先落笔、后验证"。
  这类错误最危险的地方是它**看起来完全合理** —— 数字是上一轮验证过的，只是本轮变了。

### 2.3 ⚠️ **我一度打算"修" `B1` 行里的 30 项，被自己否掉**

- **我考虑过**：`docs/todo.md` 的 `B1` 行写着"用构建产物跑 30 项界面流程全通过"，与现在的 32 项不符 → 直接改成 32。
- **否掉的理由**：那是 **`B1` 验收当时**的真实数字。改掉它等于涂改历史，
  与项目"不得事后补造"是同一条红线的两面（既不许补造没发生的，也不该修改发生过的）。
- **实际处置**：保留 30，补注"当时脚本是 30 项；A 补识别步骤后已增至 32 项，合并态在 J2 下复跑通过"。
- 同样逻辑用在 `docs/知识库.md` §10.2：PR 记录**只更新结果列**，不改写当时的判断。

### 2.4 ⚠️ **`P-A8` 的实现方案被打回一次**

- **我的第一方案**：在 `GraphPanel` 内部持有 `selected`，知识卡片通过自定义事件/回调通知图谱选中。
- **否掉的理由**：卡片与图谱是**并列的两个面板**，各存一份选择必然退化为"两套选择" ——
  点卡片后图谱仍停在上一个选中项。这不是实现 bug，是结构问题，加事件总线只是把问题盖住。
- **实际方案**：把选中状态**提升到状态层**（`useWorkbench` 的 `focusedNodeId` + `focusNode`），
  两个面板共用一份，且明确它是**纯界面状态**（不发请求、不写画像、不受忙碌态门控）。
- **附带否决**：还考虑过"让整张知识卡片可点击" → 否掉，卡片内部已有引用角标按钮，
  嵌套可点击区域会让点击目标变得不可预测；改为显式的「在图谱中查看 / 取消图谱高亮」按钮。

### 2.5 ⚠️ **一处 CSS 取值被我自己改掉**

- **我的第一版**：长文本防御写 `overflow-wrap: break-word`。
- **改成**：`overflow-wrap: anywhere`。
- **理由**：`break-word` **不参与 `min-content` 宽度计算**，而卡片处在 grid/flex 容器里 ——
  容器仍会按"这个长 token 不可断行"来算最小宽度，等于样式白设。只有 `anywhere` 会让最小宽度也按可断行计算。

### 2.6 ⚠️ **我原本要给 `docs/` 新开一个子目录，被否掉**

- **我考虑过**：为「界面验收清单」与「演示分镜」新建 `docs/deliverables/`。
- **否掉的理由**：`docs/README.md` §二把目录结构**写死了**（根目录只有三个导航文件 + 六个子目录）。
  为一个文件新开一层结构，属于未经团队决定的架构改动。
- **实际处置**：验收清单归入 `specs/`（与 `初赛补充说明` 同类，都是验收口径）；
  分镜归入 `plans/`（属本轮产出，录制待补）；**结构不动**，只在 `docs/README.md` 的 specs 表里登记新文件。

### 2.7 ⚠️ **小处：删掉了一个未使用变量，连带删掉随之无用的导入**

- `GraphPanel.tsx` 里原有一处 `const cls = status ? statusClass(status) : 'tag tag-local';` **从未被使用**。
- 本轮改这个文件时顺手删除，并同步去掉 `statusClass` 的导入（否则引入一个未使用的导入）。
- 注：删它**不影响**任何行为（`class` 属性原本就没用这个值），纯属清理。

## 4 结论

本轮**通过**，但有两条限定：

1. **`P-A12` / `P-A8` 的验收只到代码层与渲染层**，人眼验收项已全部在验收清单里标为 👁 并留待人工，
   **不记为"已完全验收"**；
2. **`P-A14` 只完成分镜脚本**，录屏属 `P-A10`，仍依赖 `P-C14` 与 `P-B15`。

本轮最有价值的产出不是新增的界面联动，而是 **`I9`**：
README 把已实现的能力写成"零实现"暴露了一个系统性缺口 ——
**文档没有人复核就会漂移，而漂移的方向通常是保守的（低报）**，这同样会削弱整份提交材料的可信度。
