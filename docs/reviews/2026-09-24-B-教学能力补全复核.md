## 二、被否决与被修改的记录（**必填项**）

> `todo.md` 要求 `reviews/` 含**真实**的"被否决或被修改"记录。以下是本轮真实发生的 **6 条**，
> 每条都写清**否决依据**，且前两条已写进代码注释（防止后来者"顺手补上"）。

### R1 · ✅ 被否决并**实测负向对照**：「缺口检查有没有牙」

`P-B15` 的核心判据是"单调性素材必须保留导数前置缺口"。第一版只写了正文，
**没有任何机器判据** —— 也就是说，**将来任何人往正文里补一句导数的定义，全部测试照绿**，
而演示路径（`MISSING → SUPPLEMENTED → VERIFIED`）静默失效。

**处置**：压成硬检查（单调性正文不得出现 `['极限','瞬时变化率','平均变化率','割线','无限接近']`），
并**实测负向对照**：往 `text/03-monotonicity.md` 追加一句"导数是平均变化率的极限" ⇒
该条**立刻变红**并给出正确诊断；改回来即恢复（27 项 0 失败）。

**意义**：这条记录证明的不是"测试通过了"，而是"**这条测试真的会失败**"。

### R2 · ⛔ 被否决：归因层 ③「诊断 Agent（模型）」

**计划书 §2.2 原本设计了第三层**：两层都推不出时，可选出动诊断 Agent。

**否决依据**：`P-B9` 的验收判据是"须给出**可核对**理由，不得仅凭答案对错断言"。
**模型给的理由同样不可核对** —— 它只是把"编造"换了个来源。为了让第三层"看起来可靠"
再加一道"必须校验到具体选项才采纳"，那也只是给不可核对的东西加一层过滤器，
**没有把不可核对变成可核对**。

⇒ **整层删除**。少一层猜测，比多一层听起来合理的解释更符合这条待办的本意。
代价如实记下：**推不出来的题会更多**，它们返回 `null` 并计入 `unattributed` —— **这是对的**。

### R3 · ⛔ 被否决：数值的倍数／反号推导（层 ② 的一个子规则）

原设计里层 ② 有一条："你选的 `6` 正好是正确答案 `12` 的一半 ⇒ 计算错误"。

**否决依据：反例就在自编题里。** `fx-der-3` 的正确答案是 `12`、干扰项是 `6`，
而选 `6` 的真实原因是**忘了把 `x = 2` 代进去** —— 与"除以 2 算错"毫无关系。
选择题的选项本来就是一组简单数，**倍数关系大多是巧合**。

⇒ **已删除**。若留着，它输出的每一条都长得像"可核对理由"，实际是
`P-B9` 点名要禁的**"仅凭答案对错断言"** —— 而且是**带数字的**那种，更容易被当成证据。

### R4 · ✏️ 被修改：切线的切点 `x = 0.5` → `x = −1.5`

**过程**：第一版图按"取个好看的切点"选了 `x = 0.5`（斜率 −2.25，切线 `y = −2.25x − 0.25`）。
**看渲染出来的图时发现**这条切线在 `x = −1` 处恰好等于 `2` ——
也就是**正好穿过曲线自己的极大值点 `(−1, 2)`**。

**这不是画错**：把切点 `t` 代进 `f(t)+f'(t)(−1−t) = 2` 解得 `(t−1)²(2t+1) = 0`，
即 `t = 1` 或 `t = −1/2`，而 `1/2` 正是 `−1/2` 的奇对称像（`f` 是奇函数）。

**为什么仍然必须改**：那张图**看着像一条在两个地方都贴上曲线的直线** ——
对"切线是什么"这个主题是**帮倒忙，比不画更糟**。

**处置**：改到 `x = −1.5`（斜率 3.75，切线 `y = 3.75x + 6.75`），另一个交点在 `x = 3`
（分解 `f(x)−(3.75x+6.75) = (x+1.5)²(x−3)` 即知），**落在图幅之外**。
**完整推导留在 `figures.mjs` 的注释里**，防止有人改回去。

### R5 · ✏️ 被修改：「每一份导数素材都要含全部定义标志词」→「合起来含」

反向断言第一版要求**导数主题的每一份**素材都含全部标志词。**跑起来就红了** ——
`voice/01` 是**口语转写**，讲的就是割线转切线，但不会说出"瞬时变化率"这种书面词。

**判据**：要求每一份都含，等于**用书面语的用词习惯去卡口语转写** —— 那是**假要求**。
假要求有两种坏结局：要么被放宽成空断言，要么逼着人把口语稿改成书面语（那才是失真）。

**处置**：改为"导数主题的素材**合起来**用到全部标志词"，并在注释里写明这是**反空跑证明**
（否则"谁都不含"也能通过）。

### R6 · ✏️ 被修改：长标注 → 单字母（`Q(2,4)` → `Q`）

**过程**：`tag()` 的白底会**盖住底下的东西**。第一版把 `Q(2,4)` 直接压在抛物线上，
白底在曲线中间**啃出一个方口**。

**这类错跑测试跑不出来**：字节一致 ✓、尺寸正确 ✓、能被 `/api/parse` 接受 ✓ ——
**只有人看一眼才知道**。

**处置**：图例条（`PLOT.bottom` 392 → 352）＋ 单字母 `P`／`Q`，坐标移进图例。
**每一个 `tag` 的位置现在都有注释写明"这块带子里曲线／直线的取值范围是多少、为什么碰不到标注框"。**

> R4 与 R6 是**同一类**：**断言全绿，图是错的**。这类错误只能靠"看"发现，
> 所以本轮把"打开生成的 PNG 看一遍"当作**必要步骤**，而不是可选项。

### N1 · ⚠️ `verify:flow` 会连到**旧服务端**，并以崩溃的形式假报"改坏了"（**真实现象**）

`verify:flow` 打的是**已经跑着的**服务端（默认 `http://127.0.0.1:3000`），**不会自己起一个**。

```

```

**实测的假象**：直接 `npm run verify:flow` ⇒ 停在 `⑩b 提交返回逐题结果（3 条） —— undefined`，
紧接着

```
TypeError: Cannot read properties of undefined (reading 'find')
    at verify-ui-flow.mjs:282
```

**看起来完全像本轮把提交链路改崩了**，实际是**连到了旧服务端**。

**正确复跑**（本轮即如此复现出 **113 / 0 失败**）：

```bash
cd apps/server && MODEL_PROVIDER=mock PORT=3131 npx tsx src/index.ts   # 另开终端
cd apps/server && FLOW_BASE=http://127.0.0.1:3131 npm run verify:flow
```

⇒ 它探的是"有没有服务端"，**探不出"服务端是不是这一版"**。

**建议**（本轮**未改**）：比对本脚本依赖的接口是否真的存在（如 `POST /api/quiz/attempt` 不返回 404），
或比对 `/api/health` 的 `build.builtAt` 与源码最后修改时间，**不匹配就明确报
