## 1 否决与修正的真实记录

### R1（否决）分支基点选错：A 的分支切自 `main`

- **AI 原始做法**：直接在 `main` 上开 `feat/a-material-path` 开始写界面。
- **实际后果**：`@lc/contracts` 解析到的是 **V1.4 旧契约**（4 态、无图谱、`GET /api/quiz`），
  前端类型检查一次性报出 **40 个错误**：`GraphNeighborhood` 不存在、`Session` 没有 `graph`、
  `HealthResponse` 没有 `verification`、`api.gap/profile` 不存在……
- **根因**：C 的契约迁移在 **PR #3 里，尚未合并**。A 必须基于 C 的分支，而不是 main。
- **处置**：把 `feat/a-material-path` 重建在 `feat/v2-contract-and-graph`（`af25d3c`）之上。
- **教训**：有 PR 依赖链时，"新开分支"的默认基点必须显式指定，不能沿用当前所在分支。
  代价是白跑一轮类型检查 —— 这本该在动手前用 `git merge-base` 或一句"契约在哪"问清楚。

### R2（修正）用 `alert()` 提示"视觉识别未接入"

- **AI 原始输出**：`alert('视觉识别尚未接入…')`。
- **否决依据**：`alert` 会阻塞整个页面、无法复制文本、与页面内其他提示样式不一致；
  更要紧的是它**丢掉了提示的上下文**（学生刚点完上传，需要就地看到说明）。
- **处置**：给 `useWorkbench` 增加 `notify()`，改为页面内 notice 条。

### R3（修正）练习提交里残留一句无意义代码

- **AI 原始输出**：提交按钮的 `onClick` 里写着 `void wb.profile;`。
- **否决依据**：这是写"上报画像"时的半成品，`void wb.profile` 只是阻止 lint 报警的空语句，
  **什么也没做** —— 界面显示"提交成功"却没有留下任何画像事件。
- **处置**：新增 `reportQuizAttempt()`，真正上报 `quiz-attempted` 事件（含题量、答对数）。

### R4（否决）不在练习提交时上报"错题归因"

- **AI 原始设想**：既然契约里有 `quiz-attribution` 事件，提交练习时顺手把错题归类
  （"计算错误"/"概念误解"），画像立刻丰富起来。
- **否决依据**：§2.6 明确要求归因"须给出可核对的理由，**不得仅凭答案对错断言**"。
  仅凭"这题选错了"就写进"概念误解"，是**编造诊断结论**并把伪造数据写进画像。
  归因需要诊断 Agent 分析学生的作答过程，属 P1 且尚未实现。
- **处置**：只上报 `quiz-attempted`；界面明确写出"错题归因尚未实现，原因是……"。
- **代价（如实记录）**：画像区的"常见误区"在真实使用中会长期为空。这是**正确**的空，
  不是缺陷 —— 宁可空着，也不填编造的内容。

### R5（否决）图谱没有边时"画一张看起来有结构的图"

- **AI 原始设想**：既然 `prerequisites` 里有 `conceptId`，可以按层布局把这些概念
  和知识点连起来，让图谱视图"有内容可看"，演示效果好得多。
- **否决依据**：`PrerequisiteRelation` **没有 `from` 字段**，它只说"某概念是前置"，
  没说"哪个知识点依赖它"。连线就是编造依赖关系，而依赖关系正是缺口判定的依据。
  这与 C 在 R5 里的判断一致 —— 两轮独立得出同一结论，说明这不是保守，是必须。
- **处置**：没有边时**只有节点**，界面明写"当前图谱只有节点、没有关系边…
  界面不会凭空连线"，并引导去看上方的「前置依赖」区（那里有真实的关系与状态）。

### R6（修正）`ProfileEvent.sessionId` 的冗余散落在 4 个调用点

- **AI 原始输出**：在 `supplementGap` / `claimKnown` / `ask` / `reportQuizAttempt`
  四处各写一遍 `sessionId`。
- **自查发现**：类型错误逼出了这件事 —— 契约要求每个事件带 `sessionId`，
  但服务端会用请求级的覆盖它，**请求侧本就是冗余的**。
  分散写意味着将来契约细化要改 4 个地方。
- **处置**：加局部 `withSessionId()` 收敛为一处，并把契约建议写进 changelog §5.2 交 C。

## 2 未被验证的事项（不得当作已验证）

1. **视觉与交互未经人工确认** —— 本环境没有 `agent-browser`，且不允许全局安装。
   验证只到「TypeScript 通过 + Vite 构建成功 + 模块可转译加载」。
   **布局是否错位、图谱 SVG 是否重叠、长文本是否溢出，全部未确认。**
2. **未在真实模型下走过一遍** —— `verify:flow` 与手工联通检查都走 `MODEL_PROVIDER=mock`。
   mock 返回的是**固定的演示数据**（1 个知识点、1 条前置关系、无图谱边），
   因此"多知识点卡片排版""有边时的图谱布局"这两条路径**从未被执行过**。
3. **刷新恢复只做了读取路径** —— `persist.ts` 写入走 `sessionStorage`，
   但"刷新后 sessionId 仍有效"依赖服务端内存会话未被回收；
   服务端重启后恢复的会话会 404，此路径**未验证**。
4. **`build` 产物不可运行** —— 见 changelog §5.1。构建"成功"不等于"能跑"，
   这次是 `node dist/index.js` 崩溃才发现的。C7 部署前必须解决。

## 4 环境坑（本轮新增，已并入 MEMORY）

- 切分支后 **39 个被跟踪文件从工作区消失**（`git status` 显示 ` D`），
  `git checkout -- .` 一条命令恢复。与本项目 9/17 早些时候记录的同一现象。
- `git branch -D` + `git checkout -b` 之后出现**未出生分支**：
  新分支没有任何提交、所有文件显示为 `A`，且原分支的本地引用丢失。
  **四个提交与远端分支均完好**，用 `git reset --soft <已知基点>` 把分支指回正确基点即可修复。
  **结论：在这个环境里，分支切换后必须立刻 `git status` + `git rev-parse HEAD` 双查。**
