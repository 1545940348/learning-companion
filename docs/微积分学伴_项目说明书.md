## 01 项目定位与初赛范围

### 1.1 项目目标

围绕导数、切线与单调性，帮助学生读懂讲义中的文字、公式和图像。系统不仅整理知识点，还指出当前学习需要哪些前置知识、材料是否覆盖这些基础，**并在发现缺口时直接补上最小必要说明**，然后继续答疑与练习。

**两条进入路径**：

| 路径 | 流程 | 适用场景 |
|---|---|---|
| **轻路径（默认）** | 拍照或粘贴 → 直接得到解释 → 可继续追问 → 按需转入材料路径 | 学生只有一道题、一句看不懂的话、一张讲义照片 |
| **材料路径** | 上传材料 → 系统解析并抽取知识点与前置依赖 → 缺口自检与补充 → 分步答疑 → 练习 → 反馈 | 学生要系统学习某个主题，或希望回答贴合自己的讲义 |

轻路径不以建立会话、上传材料为前提，也不要求用户理解任何系统概念。

### 1.2 初赛优先级

| 级别 | 内容 |
|---|---|
| **P0：必须完成** | 零材料直接提问；图文输入与识别（默认信任＋可就地纠错）；知识点卡片及轻量前置依赖；缺口识别与一键补充；补充材料与新学习分离；三类来源（数据与校验层完整、界面层降权）；交互答疑；9 道固定练习 ＋ 按材料出题；开发文档留痕；部署与参赛材料。 |
| 后续迭代 | 复杂图谱、并列／派生关系、独立语义召回系统、跨设备同步与长期画像。初赛不分配开发工时，也不作为已实现能力宣传。 |
| 初赛不做 | 整本 PDF、批量资料库、手写批改、复杂证明评分、教师管理端、账号、语音视频和动态函数绘图。 |

### 1.3 成功标准

- 线上真实接入模型，支持文字与图片；在**零材料状态**下可完成一次有效答疑。
- 完整走通三个主题的材料路径学习流程。
- 演示一次"单调性材料缺导数解释 → 发现缺口 → 一键补充 → 状态更新 → 继续答疑"。
- 回答明确区分讲义原文、基于材料的解释／推导、AI 补充内容；界面默认简洁，依据可展开溯源。
- 固定题与核心数学案例人工核验；边界、来源、会话测试实际通过。
- 交齐在线链接、源码、3 分钟视频、PPT，以及可溯源的开发过程记录（LearnBuddy 对话 ＋ 四类开发文档）。

## 02 学生学习流程与交互

### 2.1 零材料直接提问（轻路径）

学生无需上传任何材料即可提问：

- 输入方式：不超过 3000 字的文字、一张不超过 5MB 的 PNG/JPEG 图片，或两者同时提交；
- 系统直接给出解释，并标注"未基于你的材料"；回答遵循第 04 章的课程范围与边界规则；
- 回答中提供"上传讲义可获得更贴合你材料的解答"的一次性提示，不阻断、不重复弹出；
- 学生可随时转入材料路径：上传材料后，系统抽取知识点与依赖，并提示轻路径中的历史回答是否需要重新核对。

轻路径不生成知识点卡片，不要求确认识别结果，不占用材料配额。

### 2.2 图文输入与识别（默认信任＋可就地纠错）

识别结果**默认直接用于后续教学**，不再设置"确认后才更新材料"的阻断步骤。

- 识别文本以可编辑形式展示在旁，模糊或不完整的公式标注为"识别可能不准"，属于提示而非阻断；
- 学生发现识别错误可随时就地修改；修改后系统重建受影响的知识点与前置依赖，已生成的回答标记为"依据已更新"并允许重新生成；
- 无刻度示意图不据此估算精确数值；
- 为控制上下文和工期，每个学习会话最多 **3 份**材料，文本与图像描述合计不超过 **9000 字**；超限时提示缩短或开始新学习；
- 图片解析为文本／描述后参与后续教学，不反复发送所有图片。

### 2.3 知识点与前置提示（缺口即补）

展示当前会话 3—6 张核心知识点卡片，包含名称、解释、公式与条件、来源和误区。卡片下显示"学习前需要：导数""当前材料未覆盖"等提示；不绘制复杂网络。3—6 只是展示数量，依赖覆盖判定仍检查全部材料。

**发现缺口时，系统提供补齐能力而不是把任务交回学生**：

> 这部分需要导数知识，当前材料没有解释。
> 　[ 补上这一段 ]　[ 我已掌握，继续 ]

点击"补上这一段"后，系统生成当前主题所需的**最小必要说明**（通常 200—400 字），显著标注为 AI 补充内容，并入当前会话材料，依赖状态随之更新。学生也可选择"我已掌握，继续"，直接进入答疑；该选择只影响引导，不改变材料覆盖状态。

材料缺失不等于学生不会，任何情况下不锁住学习。

### 2.4 两种上传动作

| 操作 | 行为 |
|---|---|
| **补充当前材料** | 在当前会话加入新素材，保留旧材料和知识点。重建成功后更新依赖；失败保留旧状态。更新后清空当前练习选择与反馈，旧聊天仅作历史展示。 |
| **开始新学习** | 经学生确认后生成新会话，清空旧材料、知识点、关系、聊天和练习状态；AI 补充内容不随会话迁移。 |

### 2.5 答疑

保留"解释概念""给我提示""查看完整解答"三种模式。默认先给提示，完整解答由学生主动选择。

回答默认以**简洁正文 ＋ 引用角标**呈现；点击角标展开"依据详情"，可见来源类别、引用片段与所用规则。AI 补充内容不适用降权规则，始终显著标注。

### 2.6 练习与反馈

练习由两部分组成：

| 类型 | 数量 | 来源标注 |
|---|---|---|
| **固定题** | 每主题 3 道单选题 | 标注"项目自编练习"，不能伪装成上传讲义原题 |
| **按材料出题** | 基于当前会话材料生成 2 道，可重复生成 | 标注为"基于你的材料生成"，属于第 04 章的来源类别② |

提交前不展示答案，答错后解释误区并引导复习，答对后建议继续。解析注明所用规则；若依赖材料未覆盖，先提示并允许补充。学生主动尝试自编练习时，其中的解析不被计为材料证据。

## 03 轻量知识依赖与动态更新

### 3.1 依赖含义

只建模"学习当前知识点前需要了解什么"，不同时开发并列、派生或复杂关系。系统结合当前材料中的教学用法识别依赖，并给出依据；仅出现一个术语，不自动证明它是前置知识。无明确依据的推测只列为待确认提示，不伪装成课件结论。

| 状态 | 判定与行为 |
|---|---|
| **LOCAL：材料已覆盖** | 当前任一材料中有足以支持当前学习目的的定义、规则或说明，并能定位来源；不要求必须有独立讲义或展示卡片。 |
| **SUPPLEMENTED：已由 AI 补充** | 材料原本缺失，经学生点击"补上这一段"后由系统补齐。内容显著标注为 AI 补充，可定位到具体补充块。 |
| **MISSING：材料未覆盖** | 当前学习明确需要该概念，所有材料均无相应解释，且学生尚未选择补充。显示缺口并提供补充入口。 |
| **待确认** | 依据不清晰或公式识别不完整时，列为待确认；不把不确定推测直接记为已覆盖或缺失。 |

### 3.2 更新规则

- 每条前置关系包含依赖概念、状态、依赖理由与对应依据；LOCAL 需覆盖该概念的来源，SUPPLEMENTED 需指向具体补充块。
- 补充材料或补充缺口后重新检查当前关系，保留稳定知识点编号。
- MISSING → LOCAL 仅当新增材料确实提供说明；MISSING → SUPPLEMENTED 仅当学生实际点击补充并生成成功。
- 合并同义概念，排除自依赖与循环依赖；不扩展到高数全课程网络。
- SUPPLEMENTED 不因学生表示"已会"而转为 LOCAL：材料覆盖状态只由材料决定。
- 会话之间不共享 AI 补充内容；新会话中的同一概念回到 MISSING，可再次按需补充。

### 3.3 核心演示案例

初始素材讲解"依据 f′(x) 的符号判断 f(x) 单调性"，未说明导数定义。系统保留单调性知识点，标记导数前置解释缺失（MISSING），并在同屏给出"补上这一段"。学生点击后，系统生成导数定义的最小必要说明并标注为 AI 补充，状态转为 SUPPLEMENTED，随后结合原始素材与补充内容解释，并进入练习。

另备一条对照路径：学生改为补充一份导数定义讲义，状态转为 LOCAL，用于展示材料来源与 AI 补充的来源区分。

### 3.4 工程与能力边界

依赖判断由教学模块生成结构化结果，程序校验编号、来源和关系结构；教学合理性由固定案例验证。关系检查不等同于证明任意推断都正确。无需引入图数据库、图形编辑器或单独嵌入模型。

## 04 回答边界与来源规则

### 4.1 哪些问题可以回答

| 情况 | 处理方式 |
|---|---|
| 材料明确包含 | 基于对应材料回答并引用。 |
| 可依据材料推导 | 允许新例题与计算；标记基于材料的解释／推导，列出所用条件与规则。 |
| 缺少前置知识 | 说明缺少什么，同屏提供"补上这一段"；学生可补充、按需补充或直接继续。 |
| 部分支持 | 回答可支持部分，分别指出材料不足或超出范围的部分。 |
| 超出课程范围 | 说明仅支持导数、切线与单调性，引导回到当前主题。按需补充不扩大课程范围。 |
| 题目条件不足 | 指出缺少切点、区间等条件，先澄清，不把它混同于缺少知识素材。 |
| 零材料提问 | 可用通用知识回答，标注"未基于你的材料"，并遵守课程范围。 |

### 4.2 按需补充与授权

取消全局"外部参考开关"，改为**按动作授权**：授权发生在学生点击"补上这一段"的那一刻，范围仅限当前缺口。

- 未点击时，系统不主动生成任何 AI 补充内容；
- 点击后，系统生成当前主题所需的最小必要说明，显著标注"AI 补充：非上传讲义内容"，并入当前会话材料；不默认联网，也不编造外部文献链接；
- 补充内容受课程范围约束，不因补充而扩展到导数、切线与单调性之外；
- 生成过程中若学生切换会话或开始新学习，丢弃尚未完成的补充；
- 补充内容仅在其所属会话内有效，可作为该会话后续回答的依据，不进入其他会话的材料依据。

### 4.3 三类教学来源与校验

1. **来自讲义**：引用编号有效，摘录可在对应材料中找到。
2. **根据讲义解释／推导**：绑定支持规则或片段，与原文直接引用分开。
3. **AI 补充／外部内容**：仅在学生按需授权后生成，不使用伪造的讲义引用。

**数据与校验层完整保留三类来源**：每个教学内容块返回来源类型和引用；"请补充切点"等操作提示无需引用。B 校验结构、编号及摘录匹配；无效来源或未授权内容不展示为正常答案，返回可重试错误。**引用存在不等于推导正确**，数学结论仍需核验。

**界面层降权**：默认只呈现正文与引用角标，来源分类收进可展开的"依据详情"，不常驻三色标签。例外：AI 补充内容必须显著标注，不适用降权。

答疑先匹配当前知识点和相关材料，再判断依据是否足够。初赛使用已有编号、素材片段及模型结构化判断，不引入独立语义召回系统，也不声称相似度命中即可保证答案有据。

## 05 技术架构与共享接口

### 5.1 三层架构

- **前端**：React ＋ TypeScript，负责交互（`apps/web`）
- **教学模块**：独立 TypeScript 模块，负责提示词、依赖分析、补充内容生成与输出校验（`packages/teaching`）
- **服务端**：Node.js ＋ TypeScript，负责模型适配、会话与部署（`apps/server`）

单仓库、一个 Web 服务；**不用向量数据库**。

运行时采用现有 **CodeBuddy Agent SDK** 适配器，使用 WorkBuddy 账号密钥。依据负责人 2026-09-17 最新确认，**不得接入 DeepSeek API，包括开发备选、手动切换和故障兜底**；不再索取 DS 密钥或安排 DS 实测。此项为负责人最新要求，不改写赛事手册原文，也不由此推断所有其他服务的许可情况。

- 本地真实文字、图片调用已有验证记录；模型名称从响应回读，不将 `hy3`、`hy4-preview-f` 等观测值视为固定模型配置。
- 本接入方式由SDK处理端点与认证，项目不需要自行填写原始HTTP地址；这不等于上游服务不存在HTTP端点。
- 真实密钥只放 `apps/server/.env`，不得放入范例、代码或文档。部署环境遵守同样的密钥纪律。
- LearnBuddy是赛事开发／创作平台；WorkBuddy密钥、CodeBuddy SDK是当前实际接入链路，启动日志与健康接口使用真实适配器名称，不将三者混称。
- `MODEL_PROVIDER=sdk` 用于真实联调和发布；`mock` 仅供无密钥独立开发并明确标注。发布验收要求 `modelProvider=codebuddy-agent-sdk` 且 `mock=false`，还必须完成真实请求，健康响应本身不证明上游可用。
- 不把模型请求失败自动转换为DS调用或mock答案。现有DS代码仍需由C移除或封堵全部入口，本次文档修订不代表代码已禁用。

**结构化输出约束**：现有实测未兑现SDK的强制schema输出，B需使用提示词要求JSON、自行解析、运行时字段及来源校验；失败明确返回错误。若安排重试，须限制次数并遵守同一请求60秒总预算，不能把类型断言当作验证。

### 5.2 共享契约（五个业务接口＋两个辅助接口）

| 接口 | 输入 → 输出 |
|---|---|
| `POST /api/session`（辅助） | 创建新学习会话 → 会话 ID、初始 `materialVersion=0` 及空材料状态。轻路径不要求先调用。 |
| `GET /api/health`（辅助） | 无输入 → 服务版本、实际 `modelProvider` 与 `mock` 标志；不是模型可用性或整套业务验收证明。 |
| `POST /api/parse` | 文字、可选图片 → 识别文本（可直接使用）、公式／图像描述、低置信度标记；不设置确认阻断步骤。 |

| `GET /api/quiz?topic=…&source=fixed\|material` | 主题与来源类型 → 3 道自编固定题，或基于当前材料生成的 2 道题（含选项、答案、解析与依据）。答案由应用在提交后展示。 |

以上两个辅助接口已存在于代码，本次补齐说明，不新增业务能力。按材料出题还需传当前 `sessionId`；轻路径当前调用约定为 `sessionId:null`、`materialVersion:0`。字段以共享类型和经三人确认的样例为准；C需补齐会话创建与材料出题参数的类型表达，避免文档、前端和服务端分叉。

**共享类型至少包含**：会话 ID、材料版本；素材 ID 与文本；补充块 ID 与授权标记；知识点 ID 及来源；前置概念 ID、状态（LOCAL／SUPPLEMENTED／MISSING／待确认）、理由和依据；回答块的来源类别与引用。C 维护正常与失败 JSON 样例，A、B 依据同一契约开发。

### 5.3 会话与错误处理

每份材料使用独立 ID，更新材料递增版本；新学习使用新会话 ID；轻路径会话可无材料版本。响应仅在会话与材料版本仍匹配时应用；换课、补充或开始新学习时丢弃旧请求结果。补充失败不清空已有状态。

当前标签页保存材料文本、依赖和进度，刷新可恢复，**不承诺跨设备与关闭会话后恢复**。图片不长期保存，刷新需查看原图时重新上传；文本仍可追溯。模型请求超过 **60 秒**报错，可重试并保留输入。

### 7.1 自编素材与固定题

- **导数**：x² 在 1 处的差商与导数，结果为 2。
- **切线**：x² 在 1 处切点 (1,1)，切线 y = 2x − 1。
- **单调性**：x³ − 3x 在 (−∞,−1)、(1,+∞) 递增，在 (−1,1) 递减。

每个主题各准备文字与图片版本，共 6 份；单调性素材保留明确的导数前置缺口，同时支持"一键补充"与"补充讲义"两种补齐方式，用于演示来源区分。固定题每主题 3 道。B 初审数学内容，A 依据核验清单复核；分歧未解决不得进入演示。

|---|---|---|
| E1 | 单调性材料仅提导数，没有解释 | 标 MISSING，同屏提供补充入口；不自动生成 AI 内容。 |
| E2 | 原文解释导数，但未显示导数卡片 | 判 LOCAL；不能因为卡片缺席误判材料缺失。 |
| E3 | 补充导数素材／补充无关素材 | 前者转 LOCAL；后者保持 MISSING，不伪装已补齐。 |
| E4 | 新例题可依材料计算 | 允许推导并标注依据，不因原文无该题就拒答。 |
| E5 | 完全越界／部分可答 | 完全越界引导返回；部分问题分开回答。 |
| E6 | 未点击／点击"补上这一段" | 未点击不生成任何 AI 补充内容；点击后生成、显著标注、状态转 SUPPLEMENTED 且不超课程范围。 |
| E7 | 模型返回假引用或未授权内容 | 校验失败，不能作为正常答案展示。 |
| E8 | 换课时旧回答迟到 | 新会话不出现旧素材、旧回答或旧练习反馈。 |
| E9 | 补充失败、刷新、达到素材上限 | 失败保留旧状态；刷新恢复材料文本；超限有操作提示。 |
| E10 | 会话 A 的 AI 补充内容与会话 B | 补充内容不进入会话 B 的材料依据；B 中该概念回到 MISSING。 |
| E11 | 零材料直接提问 | 可完成有效答疑并标注"未基于你的材料"；上传材料后回答改为引用材料。 |
| E12 | 识别结果有误，用户就地修改 | 无需重新上传；知识点与依赖随之重建；已生成回答标记"依据已更新"。 |
| E13 | 补充生成中切换会话 | 丢弃未完成的补充，不产生半成品内容或越权状态。 |

### 10.2 执行责任与发布条件
