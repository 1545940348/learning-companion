## 四、命名规范

- **四类留痕文档**：`YYYY-MM-DD-<主题>.md`，日期为**实际撰写日**（不是事件发生日）
- 成员归属可选前缀 `-A-` / `-B-` / `-C-`，用于同一轮内区分三人产出
  例：`2026-09-17-第6轮-C-契约迁移与图谱落盘.md`
- `specs/` / `designs/` / `archive/` 中的文档用**描述性原名**（不加日期前缀），
  版本信息写在文件头（如"当前 V2.0"）
- 根目录三件套用固定名：`README.md` / `知识库.md` / `todo.md`

## 五、一轮开发的文档流程

```
plans/     每轮开始前写：目标、任务分解、验收条件、允许修改目录
   ↓
（动手；与 LearnBuddy 的对话记录即本轮的原始凭据）
   ↓
changelogs/ 每轮结束后写：改了什么、为什么、影响模块、验收结论
reviews/    每轮结束后写：AI 产出核对，必须含"被否决或被修改"的真实记录
tech/       有重大决策时写：选型、契约变更、取舍理由、已知限制
```

**硬性要求**：每轮至少一条 changelog，且与当轮 LearnBuddy 对话一一对应；
**不得事后补造**。契约变更必须同步 `知识库.md`、`packages/contracts` 与 `tech/` 三处。
